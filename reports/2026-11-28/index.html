空间智能与通用 AI 科研晨报 ｜ 2026-11-28

本期检索窗口为 2026-11-25 09:00—2026-11-28 09:00（Asia/Shanghai），优先最近 24 小时，再回溯 72 小时。与 27 日晨报去重：ABot-World、WorldExpand、WorldInteract、PhysReader、Cairn、WorldReforge、X-Harness、RoboEvo² 等，没有核实到需要重新展开的新证据，不重复。当前可访问的 arXiv RO/CV/AI/LG 最新公告及 Robotics 新稿页仍为 26 日；下述论文多为 25 日 UTC 提交、26 日公告，不是 28 日首发。今日将窗口内尚未展开的论文与官方新增资源一起评估，并单独记录重大遗漏回补和窗口外追踪。

今天最重要的判断是：持久世界需要可修正的记忆，动作预测需要一致的输入接口，自进化需要后续任务上的可验证收益。 这三种能力都不能由演示视频或一条总分曲线替代。官方新增中，LingBot-Map 2.0 / LingBot-Navi、RoboRSI 新技术文章与复现入口值得优先检查；尤其要区分“技术报告中的完整系统”和“当前公开基础模型”。本期展开 11 项，末项保留已核实 API 文档的 3D 产品发布；不把媒体报道日期直接当成模型或论文首发日期。

今日精读顺序

今天我建议的精读顺序是：LingBot-Map 2.0 / LingBot-Navi → ActRosetta → AgenTAP → Dianjing → EvoLink-Bench。

  • LingBot-Map 2.0 / LingBot-Navi：先理解空间记忆如何修正、复用和影响下游导航，同时划清 GCR 与公开基础权重的边界。
  • ActRosetta：在比较世界模型之前，先确认训练和评测是否真的给了模型同一种动作。
  • AgenTAP：看通用视觉推理如何补足长时点对应，再检查这类昂贵标注是否改善较便宜的专用模型。
  • Dianjing：看强视频先验需要多少动作适配，重点读训练噪声分配和真实动作结果评测。
  • EvoLink-Bench：最后检查记忆、自修改和失败重试究竟有没有帮助后续任务，避免混淆三种收益。

如果今天更关注开放机器人 Agent，先读第 3 项 RoboRSI 的 27 日技术文章；若更关注训练方法，接着读第 9 项 Maco-RL。二者分别更新模型与工具的协同方式、跨任务 RL 的数据和计算分配。

重点论文 / 模型 / 项目

1. LingBot-Map 2.0 / LingBot-Navi：修正空间记忆，并让下一次任务用上它｜P0

Reconsolidatable Streaming 3D Reconstruction；Yihang Chen、Lin-Zhuo Chen、Jian Gao 等；Scene-aware Navigation with Spatial Memory；Huanhang Hu、Xiao Li、Lingyuan Yang 等，蚂蚁灵波 Robbyant。 Map 公开仓库实际初始发布为 26 日 17:38 UTC，Navi 为 26 日 14:20 UTC；27 日有公司发布传播。属于官方技术报告、推理代码与模型发布，未核验同行评审。Map 项目与报告｜Navi 项目与报告。Map README 的 21/23 日 News 行早于当前可见仓库提交，不能据此精确确定更早资源的可用范围。

Map 解决长视频流中旧 KV 记忆积累几何漂移的问题。GCR 保留低层局部几何，只让高层跨视图关系切换到双向注意力，重算历史关键帧并写回缓存，再继续因果流式预测。 训练联合覆盖流式、重整及二者转换，监督深度、绝对/相对位姿并统一尺度。Navi 则把表面位置与视觉语义特征组成 3D tokens，在局部块内和跨块注意力间交换信息，用 Qwen3.5-4B 支撑目标落地、图像定位和 frontier 预测；flow-matching 路线头与局部规划器完成导航。它不要求先把所有块精确对齐成一个全局地图。

作者报告，VBR 长轨迹 ATE 为 Map 1.0 的 31.12m → Map 2.0 在线 17.01m → GCR 4.72m；约 85% 是对旧版本的总改善，GCR 相对新在线基线约 72%。Navi 的 GOAT-Bench 68.60%使用模拟器深度、位姿和路径执行；完整 GOAT 上用重建几何、自行生成动作时是 40.76%，自建完整测试是 26.28%。只把 Map 1.0 换成 2.0、导航权重不动，分别增加 4.15、2.35 点。所有 Navi 闭环实验都先有模拟器辅助探索，不能解释为从零自主探索的同条件胜出，也没有第三方复现。

最值得读的是缓存修正与下游接口，而非单个榜单名次。 相对 VGGT 类重建、外部 SLAM 后端和场景图记忆，它把修正写回模型上下文，并直接测试导航收益。但公开 Map 仓库明确 without GCR：基础权重实际可列出约 4.63GB 文件，API 为公开、非 gated，README 的“private”提示已落后于当前元数据；不能据此声称 GCR 已开放。Map 原创代码/权重为 CC BY-NC 4.0。Navi 代码与模型标 Apache 2.0，模型约 16.13GB，另有约 34MB 局部规划器；511 场景含 475 训练、36 留出，数据需人工审批，不能称无门槛全量下载。轻量验证先在短回环序列检查位姿/深度输出与尺度，再在同一目标、同一导航权重下比较两版地图；GCR 工件未开放前，只能设计对照，不能冒称复现完整纠错系统。

2. ActRosetta：修正动作接口就可能改变世界模型排名｜P0

Was the Model Given the Right Action? Auditing and Repairing Action Interfaces in Navigation World Models；Ajmain Istiak Apon、Md Mehedi Hasan、Sejuti Rahman，University of Dhaka 与 New Uzbekistan University。25 日提交、26 日公告；预印本，未核验同行评审。 论文与完整审计附录。它已进入上一期候选池，本期因独立审计价值展开，属于 Selection 后的阅读安排调整，不是新检索回补。

研究问题很基础：评测时的动作是否与模型训练时含义一致？作者在 Meta NWM 找到三个相互作用的差异：每块局部坐标与首次坐标、归一化偏置添加范围、yaw 环绕规则。工具在静止、平移、旋转及跨角度边界的受控路径上分别调用训练/评测编码器，恢复兼容的接口约定；只有证据足够且转换可逆才修复，否则拒绝归因或保留不确定性。它没有新模型训练损失；NWM 的主要修复直接使用原训练编码器，并不依赖工具成功猜出接口。

审计作者报告，150 个 RECON 片段、1–16 秒预测的 DreamSim 均值 0.240 → 0.139，下降 42%，不更新权重；只修偏置反而更差。匹配重跑中，EgoWM 的优势反转，RAE-NWM 与修复后 NWM 的差值区间包含零，但不能据此宣称两者等价。最终人工团队内部封存的 240 对编码器测试中，91 对差异全部检出，73 对精确恢复差异，可输出转换的 38 对全部修复；测试由独立自动 Agent 编写，不是外部研究团队第三方验证。默认 NWM 规划代码走另一条正确路径，不能把 rollout 问题外推为原规划结果失效；本文也未证明闭环控制改善。

非常值得深入阅读。 它补充 WorldOracle、WorldEcho 等“是否服从动作”的评测：先检查动作有没有被正确表达。局限是接口假设族、探测范围和真实仓库覆盖有限；对动作基本不敏感的模型，修复收益也有限。本轮未核验 ActRosetta 专属代码/数据发布，不把原 NWM 仓库当成新工具代码。轻量验证完全可以从 CPU 开始：对训练/评测两条编码路径输入转弯后平移、跨 ±π、非零初始朝向及至少三块动作，逐块比张量；再用少量固定噪声的预测测试，报告完全修复与单项修复，最后才检查控制收益。

3. SenseNova-RoboRSI-27B：新技术文章、复现脚本与量化权重补齐开放接口｜P0

SenseNova-RoboRSI-27B: Integrating VLA and Code as Policy Through Model–Harness Co-Evolution；商汤 OpenSenseNova 团队。正式模型 README 标 23 日；本窗口新增是 26 日 RoboDojo 复现指引、27 日双语技术文章及 GGUF 链接。 属于官方模型、软件与技术文章，未确认独立同行评审。技术文章｜代码｜权重。本期依据这些新增工件回访，不能把它改写为 27 日第一次开放模型。

它把调用 VLA、审查候选轨迹和 Code as Policy 放进同一视觉语言 Agent。三轮中先由教师 GPT-6 Astra 用当前工具执行任务、据反馈修 Harness，再生成筛选后的交互轨迹对 27B 做 SFT；VLA2Agent 又从既有示范提取末端目标监督，补充长轨迹中的稀疏动作目标。相对只让 VLA 执行整段，模型可以只执行一部分轨迹，再用代码修正夹爪目标。跨模拟器 RL 与更自主的工具自优化是未来方向，不是本次已经完成的训练结果。

官方报告，新 RoboDojo Agent 协议均分 34.7 vs Preview 10.0；GPT-6 Astra 的 27.6 引自 benchmark 团队榜单，其余带星比较主要由商汤在 seed 0、layout 0 重跑，不等于所有模型完全同源的独立评测。Piper 抓放 6/10、Piper X 叠块 9/10，双臂魔方是一次完整演示，不能由此推出通用可靠性。27B 具身后训练只用仿真，但 Piper X 所调用 VLA 的训练混合仿真任务轨迹和另一个真实任务的示范，故“整个系统没有用任何真实机器人数据”不成立。旧 Harness 的 57.10 等分数与新模型 34.7 协议/对象不同，不可横比。

值得精读数据构造和失败后观测。 它与 RoboEvo²、X-Harness 共同强调工具和策略协同，但不能把教师修复、SFT 和完全自主 RSI 混为一谈。主模型实际可见 12 片合计约 54.71GB safetensors；Apache 2.0。GGUF列出约 16.74GB 的 Q4_K_M 和约 0.93GB 的视觉投影器，均须配套运行；公开清单不是量化后闭环性能验证。完整训练轨迹、成本和跨场景真机重复实验尚不足。轻量验证优先固定 10 个场景、模型与工具版本，分别禁用轨迹审查/代码纠正，测最终成功、误判完成和端到端时间；量化版本先做同输入工具调用一致性，再做闭环回归。

4. Dianjing：强视频先验需要的动作适配，可能比架构改造更少｜P0

Most of the Way There: Turning a Strong Video Prior into an Action-Conditioned World Model；Zanyi Wang、Xia Chen、Liu Liu 等，UC San Diego、地平线、南京大学、HKUST 与浙江大学。25 日提交、26 日公告；预印本，未核验同行评审。 论文｜项目。上一期已检索到，今天展开其训练分配与动作落地机制。

它问的是：视频模型已经学到大量运动知识后，是否需要重训大部分权重才能响应物理动作？方法冻结 33B MiniMax H3，用统一 EEF30 末端表示，经 AdaLN 动作投影和 rank-32 LoRA 注入；训练更集中在决定布局和运动的高噪声区间，跨块直接保留末尾三个干净 latent 作为下一块历史，不反复解码再编码。目标仍是带动作条件的视频去噪，重点是噪声采样、时间对齐与利用原生历史接口，而非添加独立奖励模型。

作者报告，只训练 114M / 0.34% 参数，约 65 小时、两个机器人本体的数据，32 张 H20、八个 epoch。在 WorldOracle 官方测试服务中以 HWM-AC 提交，AgiBot-Core 73.48、YAM-Core 70.71、Policy 64.25、YAM-Long 54.76，五轨中四轨最高，AgiBot-Long 56.43 排第二。这是作者提交到外部评测服务的预测质量分，不是四类机器人成功率，也不是第三方完整复现。65 小时是本次机器人适配数据，不包含 33B 骨干的大规模预训练成本。

值得深入读消融。 相对 Ctrl-World、GigaWorld、GE-Sim 等更复杂适配，它提供“先把先验、噪声与接口用好”的对照，但物体位置、朝向及细状态仍偏离，长时误差累积，也尚无策略训练收益的充分证据。本轮项目主要有论文和可视结果，未确认专属训练/推理代码、LoRA 和数据包可下载；上游开放不等于本方法开放。轻量实验可在可运行的小视频骨干上，保持动作接口和样本数一致，只比较均匀/高噪声加权训练，再交换或置零动作，分别测机械臂和物体状态，不能只比视觉质量。

5. AgenTAP / EgoTAP-4D：视觉 Agent 开始做物理表面点的重识别｜P0

Tracking Any Point with Agentic Visual Reasoning；Xuweiyi Chen、Jin Yao、Linzhan Mou 等，University of Michigan、University of Virginia、Meta 与 Princeton 联合团队。25 日提交、26 日公告；预印本，未核验同行评审。 论文与数据构建细节。它研究的不是认出同一个杯子，而是杯子转向、遮挡后还能否找回同一个物理表面点。

Agent 从坐标/可见性假设出发，自选放大区域、查看前后帧和叠加图，必要时拟合局部仿射/单应关系，用专家追踪器候选帮助验证，再修正答案。主体 VLM 不做对应关系专属微调，优势来自主动取证与推理，而非固定裁剪。EgoTAP-4D 将几何、专用追踪、物体动静判断和 Agent 重连接合：3,740 个 Xperience-10M、1,659 个 Ego-Exo4D 视频共 297.2h，深度和位姿提升到 3D，过滤不可靠位置；这不等于对全部 297.2h 都做了 VLM 人工级验证。

作者报告，2,000 个 TrackingBench 查询上，完整视频 AgenTAP + GPT-6 Astra 的 AJ/APD/OA 为 58.5/73.9/88.2；高分辨率 AllTracker 为 56.1/67.9/80.2。两个图像输入下，主动工具、不用专家候选也明显胜过固定放大。582 个重现点人工审计中，Agent APD 76.9，人与人一致性 79.3，最强专家 40.1；这是作者组织的标注核验。给作者复现的 D4RT 加 EgoTAP-4D，四数据集均值 AJ 39.74→41.82，但 DexYCB 定位下降，不能称全面改善。每查询输入约 141K–184K tokens，并非实时追踪替代品。

值得精读“昂贵 Agent 标注、便宜专用模型学习”的连接。 相对 CoTracker、TAPNext、AllTracker，它擅长跨消失间隔的身份复核；局限包括闭源后端、视觉别名、深度误差与已有视频可能被预训练见过。论文另建 15 个新视频、1,814 查询的留出核验；不能据此完全排除污染。项目已链接 TrackingBench，但代码按钮仍写待发布；EgoTAP-4D 完整包与新 D4RT 权重未确认。轻量验证只挑 30 对“离开再返回”的图像、每对几个点，盲标参照并限制调用预算，对比固定放大、主动检查及专家候选；先测增量价值，再考虑扩大标注，遵循原始视频源许可。

6. Agentic LongLive：异步记忆保一致性，但额外 GPU 与开放范围要单算｜P1

Agentic LongLive: Asynchronous Agentic Memory for Long Video Generation；Shaoteng Liu、Shuai Yang、Wei Huang、Luozhou Wang、Song Han、Yukang Chen，NVIDIA、MIT 与 CUHK。25 日提交、26 日公告；预印本与代码发布，未核验同行评审。 论文｜项目｜代码。它处理交互长故事里人物、物体、场景重现时失忆的问题。

独立 GPU 上的 Agent 只读已经揭示的提示词，不读生成视频，维护实体文本状态与图像，为下个镜头预制全局/局部记忆图，再由辅助 GPU 预填生成器 attention sink。单向信息流阻止视频错误反写记忆，但也不能验证视频是否真的执行了事件。小语言规划器以 RL 学“在不知道下一条提示前记什么”，奖励结合事后文本状态与经过下游视频结果校准的图像项；不是把未来脚本提前提供给 Agent。

作者报告，LongStory-Online 25 故事、857 镜头上，同一 LongLive-2.0 骨干的状态准确率 38.2→64.5，身份 44.1→89.0，重访地点 15.0→55.4。H100 表中的约 0.9% 时间增量使用独立辅助与 Agent GPU，并非计算成本只增加 1%；该配置约 15.9 FPS，未达 24 FPS 播放要求。BF16 优化后在一台 8×B200 节点上，实际六 GPU 分工的系统达 34.3 FPS；H3 版本是不同配置，不能混用耗时与质量数字。作者还展示 14 分钟故事，仍不是物理持久世界的闭环验证。

值得读异步提交和记忆污染的取舍。 相对单纯 KV 延长，它用显式实体记忆补回重现信息；局限是额外硬件、路由错误、生成状态无法自动核实。本轮代码、评测故事及部分上游模型可见，但 README 明确 RL planner 权重 coming soon，训练数据不随包发布，可先用冻结规划器，不能宣称完整主表已可原样复现。轻量验证在 5 个短故事中固定生成器，比较无记忆、同步/异步记忆；分别记录状态是否正确、是否回滚到旧状态、每镜头等待与总 GPU 秒，避免把低等待当低成本。

7. DynMF2：以少量刚体运动解释单目 4D 场景｜P1

DynMF2: Rigid Motion Factorization by Expectation-Maximization for Monocular 4D Reconstruction and Motion Segmentation；Agelos Kratimenos、Yile Hua、Kostas Daniilidis，University of Pennsylvania 与 Athena RC。25 日提交、26 日公告；预印本，未核验同行评审。 论文。它已在上一期候选池，今天作为独立 4D 重建主线展开；单目重投影允许点沿视线漂移，仅靠像素拟合并不能确定真实运动。

方法从 3D 轨迹直接做 EM：M 步闭式拟合每个刚体的 SE(3) 运动，E 步将点分配给最能解释它的运动；每点只属于一个运动，不做多个运动的加权混合。随后 requery 补漏点、merge 合并共同运动、split 分离不同运动，并把背景作为相机解释的一个运动。形成 3DGS 后再以颜色、轨迹、深度及时间平滑损失优化；“无需渲染”仅指运动分解步骤，不是整个重建不渲染。

作者报告，iPhone 指定五场景的新视角 PSNR 18.05 vs SoM 16.72，NVIDIA 七场景为 23.83 vs 23.37；完整 iPhone 跟踪 EPE 0.058 vs 0.082。它不需要动态物体掩码，薄结构和远处小运动有优势。MOVi-F 运动分配 ARI 0.775，但不同运动/部件指标并非全面超过 MoSE3；要保留轨迹输入、传感器深度与评测掩码差异。这些均为作者实验，没有外部复现。

值得读运动表示与重建之间的分工。 相对原 DynMF 的混合运动、SoM/MoSca 的运动场，它把可解释刚体结构做成约束；深度与追踪质量仍是瓶颈，非刚性形变只能用更多局部刚体近似。本轮未确认专属代码和优化场景包发布，也没有新的通用模型权重可宣称。轻量验证先对带噪声的合成 3D 轨迹运行 EM，比较单运动分配与软混合，保留遮挡、两个共同运动物体、铰链转动和非刚性四组；再挑一个短视频验证，不必先跑整套高分辨率 3DGS。

8. EvoLink-Bench：把保留状态、失败恢复与真正的跨任务学习分开测｜P0

EvoLink-Bench: A Benchmark for Evaluating Self-Evolving Agents in Long-Horizon Interdependent Task Streams；Wei Chen、Xiaodong Lu、Weihao Shen 等，北京航空航天大学。25 日提交、26 日公告；预印本与评测代码发布，未核验同行评审。 论文｜代码与数据说明。研究问题是：Agent 写下了一次经验，之后真的更会做事了吗？

它构造有依赖关系的长期任务流，将可语言表达的知识更新设为 L1、执行能力及流程复用设为 L2；用 Reset、Frozen、Evolving 区分每轮清空、只保留状态、保留并允许显式轮后更新。普通做任务留下的文件不自动算学习，重试修好当前题也不自动算迁移。它没有统一的模型训练目标，而是记录框架适配器的更新、实际提交的状态与后续探测任务结果，任务按各自验证器评分。

作者报告，五框架、三骨干配置、选定 cohort 共 19,635 个评分槽位，不是 19,635 个独立任务。DeepSeek V4 Flash 的 L1 上 Adaptive Auto-Harness Frozen→Evolving 为 76.57→92.15；GLM-5.3 的 L2 上 OpenCode 却为 76.12→72.22。Terra 的 OpenCode L1 保留状态大增 36.37 点，L2 仅增 0.07，说明知识记忆与执行能力收益不同。各骨干的任务 cohort 不同、部分适配器没有原生轮后 learner、调用预算不统一，因此这些是描述性比较，不能全解释为自更新的因果效应，也不能用于统一模型排行榜。

建议精读协议和适配器语义。 相对只计任务总分或只看重试的 benchmark，它更明确要求长期依赖与知识修订证据。MIT 评测代码、适配器、schema、离线示例和数据访问说明公开；Google Drive 数据包有入口，完整实验还需授权任务包、评分资产和运行配置，本轮未下载核验全包。轻量验证选 8 条、每条 6–10 任务的同 cohort，固定模型调用预算，对比仅留文件、结构化经验、允许修订三组；把评分器与参考答案隔离，报告后续收益和被旧经验误导的回归，脚本 smoke 通过本身不能证明自进化。

9. Maco-RL：混合任务训练的收益，取决于梯度和 rollout 如何分配｜P1

Maco-RL: Scaling Agent Capabilities with Mixed-Task Reinforcement Learning；Jiacheng Zhang、Qixing Zhou、Haiyang Wang 等，中科院自动化所与华为。25 日提交、26 日公告；预印本，未核验同行评审。 论文与资源、失败案例附录。它研究多领域 Agent 能否直接共训，而不是每域先训专家再蒸馏。

方法以跨环境配额组织异步 rollout，使每次更新包含所需领域，减少快任务挤占慢任务的梯度；再用 Frontier / Reinforcement / History 三缓冲区分配探索、巩固与保留，默认预算 20%/60%/20%。RLOO 用每题八条轨迹估优势，多个环境梯度混合；新增领域时继续扩展同一策略。数据筛选、队列版本与丢弃过时轨迹都是训练方法的一部分，不能只复刻一个采样公式。

作者报告，Qwen3.5-27B 五项指标的综合均值 43.6→54.2→60.1，更强 Qwen3.8-27B 经后训练为 61.4→67.0。混合模型与三专家在单独成本对照中，最佳已见均值为 68.41 vs 64.28，统计 GPU 小时约 12,572 vs 13,091，包含共同初筛与重启，输出 tokens 口径不含提示/工具观察。它不是相同总推理预算下的普适领先。作者也记录从 Git 历史/副本恢复参考实现，以及宽松 LLM 评分导致奖励坍塌；修复环境是收益成立的重要前提。

值得读稳定性和失败案例，优先级低于前述接口与评测论文。 相对单域 RL，它把扩展任务和保留能力放在同一调度问题里；主要实验需 64 训练设备及另配 32–40 推理设备，尚不能从较少 policy updates 推出普遍便宜。本轮未确认专属代码、模型权重与完整训练任务包，训练超参数描述不等于可执行发布。轻量替代可在 0.5–3B 模型、两个可验证小任务域做固定 token 预算对照，只改 FIFO/配额与三缓冲采样，单独统计旧任务回归、无效轨迹、等待时间和评分漏洞。

10. Hugging Face Swarms：一个可检查的小型通信 RL 实验｜P1

Swarms, Flocks, Gangs: How to build, train, and evaluate multi-agent systems；Ben Burtenshaw、Kashif Rasul，Hugging Face。26 日官方技术博客与 TRL 示例。 官方文章｜代码。这是非 arXiv 官方工程/实验发布，关联的 s³ 论文早于窗口；博客实验不是新同行评审结论。

四个逻辑 Agent 共享 Qwen3-0.6B，每人只见一个私有数字，通过消息与收件箱工具合作排序；任一成员给出完整排序即成功。每题八次团队尝试，以成功乘 token 惩罚构成团队奖励，再用组内相对优势训练，共享同一团队优势。它能检验小模型是否学会传递必要信息；由于单 Agent 根本拿不到其他私有数字，不能检验同预算下多 Agent 是否优于单 Agent。

HF 自己报告，75 次更新前后五批的训练成功 6.56%→82.34%，每团队生成 tokens 12,827→8,026；最终仅 32 个留出题通过 26 个，81.25%。37.4% token 降幅来自训练批，未保存对应留出效率统计；不要拿原论文 200 更新的 93.2% 混作此实验结果。原实验用一张 H200 训练、七张做 rollout，教程两 GPU；0.6B 参数量并不等于只需低端单卡。

值得作为可复现机制起点。 相对投票和独立重试，它明确让通信成为策略的一部分，但数字排序不能证明真实科研协作或大规模 swarm 扩展。TRL 示例实际含训练/评测/harness 和检查点入口；其 README 另记 50 更新、2×H100 约 4.8h、192 留出题成功 60.9% 的运行，不能与博客 75 更新的实验拼接成一条曲线。轻量验证先脚本重放消息协议，检查是否隐藏共享信息；再缩短上下文和训练题池，保留独立留出题、消息消融与总 token 账单。验证真正协作收益，还须另选单 Agent 本来就可解的任务做同预算对照。本轮未运行 Jobs。

11. HY-3D-3.6：3D 资产生成的正式 API 进入候选，物理可用性仍需另验｜P1

HY-3D-3.6；腾讯混元团队。官方专属调用文档标 25 日 21:44 更新，27 日集中发布报道；属于产品/API 发布，不是开放权重论文。 官方调用指南｜官方模型列表。这项在重大遗漏检查中补得，不能因没有 arXiv 就排除；API 文档的窗口内证据也比新闻日期更具体。

它面向由文字或参考图生成可导出的 3D 资产。官方接口明确区分完整模型与纯几何输出，提供 PBR、2K/4K/8K 纹理、是否把输入光照烘入贴图等控制，并以提交/查询任务返回 OBJ、GLB 等资源。这些是可核查的产品接口，不是对训练方法的完整披露；3.6 的损失、训练数据、参数规模及系统性消融未在该指南说明，本期不从旧混元架构或媒体转述补写。未见可用于严谨横比的独立定量 benchmark；面数与纹理分辨率也不能替代几何准确度或编辑可用性。

值得跟踪资产接口，精读优先级低于机制论文。 相对昨日 Tripo H3.5，它提供另一种生产资产入口；当前没有确认专属开放代码、权重和训练数据，未调用付费服务。轻量验证可在获得合法样例或既有导出后，对 10–20 个物体检查水密性、法线、薄结构、缩放、纹理固有色与重光照，再增加碰撞体、质量和关节验收。外观逼真与 PBR 不代表真实材料参数，OBJ/GLB 导出也不等于 real-to-sim 已完成；跨产品比较应固定输入、后处理和总费用。

今日研究机会与轻量验证

先做动作接口审计。 准备 20 条短轨迹，含静止、转弯、跨角度边界和非零初态；固定模型、相机、噪声种子及 action chunk。先逐块核对坐标、单位、偏置、角度、时间与夹爪语义，再做正常/互换/置零动作预测。接口一致与动作被使用是两项不同结果，任何一项不通过都不应先做大规模模型排名。

空间记忆验证从“回来看同一个地方”开始。 在少量短回环和物体搬移场景中，固定导航策略，比较旧地图、新在线地图和可用的显式修正基线；报告 ATE、目标定位、路径成功和过时记忆引发的错误。GCR 未开放时如实使用替代基线，不把外部位姿图当作原方法复现。

人类视频采用主动复核，而非全量大模型标注。 先在 30 对返回视野的图像上建立盲标参考，测专家追踪器不确定性是否能筛出最有价值的 Agent 查询；同时保留被复核改错的比例。用固定标注预算比较随机查询和不确定性查询，再小规模训练专用模型，看新数据是否改善未见场景，尤其检查 DexYCB 类回归。

自进化要给每次更新安排后续“考试”。 对同一组任务流保存模型、Harness、经验与验证器版本，设计知识修订、技能复用和无关任务干扰三类探测；比较“保留但不更新”“仅工具变更”“仅模型变更”“联合变更”。总账单含教师、失败尝试、环境执行与验证，不用成功轨迹数量或局部 token 节省代替完整收益。
