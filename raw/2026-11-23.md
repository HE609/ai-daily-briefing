检索窗口为 **2026-11-20 09:00—2026-11-23 09:00（北京时间）**，与 22 日成稿及此前重点去重。本轮并行覆盖 arXiv RO/CV/AI/LG、机构官方发布、GitHub/Hugging Face、独立的 Spatial Intelligence / 3D-4D / real-to-sim 主线、VLA/WAM/RL，以及 Agent/self-evolution，并完成 broader-web 重大遗漏检查。最新可读 arXiv 公告仍为 20 日；公告日、论文提交日、权重上传日和媒体报道日分别记录。本期保留 **6 项发布或评测更新**，不把周末转载当成新论文，也不机械重复 Inkling、World-delta、Direct3D-V3、O²LaF 和 WALL 预览。

## 今日精读顺序

今天我建议的精读顺序是：**Waddle-1 → NAT / LeRobot → Tesla Reality View → RoboColosseum 新结果 → Hy4 开放权重**。

- **Waddle-1**：先看完整系统如何调用局部策略，再检查跨尝试记忆、预算和完整成功率。
- **NAT / LeRobot**：把动作压缩、因果解码、流式执行和实时分块连起来，已有可检查的代码与权重。
- **Tesla Reality View**：研究控制与可视化共享视觉特征的工程边界，避免从演示推断物理闭环能力。
- **RoboColosseum 新结果**：理解相对排名、不确定性与绝对任务完成之间的差别。
- **Hy4**：关注开放多模态 Agent 底座与部署结构，读方法和限制，再决定是否投入大规模推理。

P0/P1/P2 表示阅读与跟踪优先级，不代表同行评审、独立复现或产品成熟度。

## 1. Waddle-1：高层 Agent 与局部策略的系统组合｜P0

**发布方：Waddle Labs；团队技术文章署名 Hanming Ye、Yiding Song。11 月 20 日 21:10 UTC 公布 Waddle-1，属于官方系统/API 预览与外部机器人评测更新，未核验同行评审。** [官方公告](https://x.com/theWaddleLabs/status/2123886705824452927)｜[团队方法背景](https://waddlelabs.ai/research/introducing-waddle)｜[系统接口说明](https://waddlelabs.ai/developers/waddle-stack)｜[Robocurve 原始结果](https://robocurve.org/)。研究问题是：能否利用已有 LLM 的推理、工具使用与代码能力，减少每个新任务都重新收集示范、训练整套策略的成本。

官方将其描述为云端 LLM 指挥本地低层策略的双臂机器人系统。较早的团队文章将接口分为硬件 SDK、IK/规划等工具层和负责模型路由、上下文管理的 Agent 服务；这是方法背景，不能当作 Waddle-1 所有模块、模型身份和参数的版本说明。相对 Code as Policies、SayCan、VoxPoser，价值在持续闭环执行与可复用工具的完整系统集成。本次没有公开新的基础模型训练目标、完整训练数据或可归因的模块消融。

**外部评测方 Robocurve 报告** RoboDojo-RC Tier 1 平均进度 **81.4%**，GPT-6.2 Astra 对照为 65.7%。本轮重算其公开记录：六任务各 20 次，共 **120 次，64 次完整完成、55 次部分完成、1 次零进度，完整完成率为 53.3%**；平均时长约 7.37 分钟。原始执行日期是 11—17 日，20 日是结果公开节点。Waddle 每任务保留一个会话跨尝试使用、每次限时十分钟且不限模型调用；对照 LLM 每次新会话、最多 40 次调用。因此这是外部测得的系统表现，尚不能归因为单模型更强或严格无经验的零样本学习。网页的每次 2.46 美元采用计划费率估算，原始 Waddle 记录的费用、调用数和 token 均为空，缺少实际账单证据。[公开记录入口](https://robocurve.org/all-runs/)

**值得优先精读评测协议。** 核心 Agent 服务闭源，API 需申请；未见完整策略权重和训练语料，公开视频与日志支持审计但不能重建全系统。轻量验证可用开放 LLM 加同一套 IK/局部策略，在六任务中交叉比较“每次清空/跨尝试记忆”和“固定调用/固定墙钟”，分别报告平均进度、完整成功、人工干预与成本。先隔离记忆和预算贡献，再讨论系统的泛化优势。

## 2. NAT：动作 token 的时间顺序进入 LeRobot 执行链｜P0

**完整标题：NAT: Scaling Causal Neural Action Tokenizers Across Embodiments。** Ahad Jawaid、Alexander Swerdlow、Yu Xiang；论文列明后两位来自 Stanford、UT Dallas，第一作者未列机构。入选依据是 **11 月 21 日 18:26 UTC 合入 LeRobot 的 PR #5416**，而非今日首次上传权重：450M 策略权重初始提交为 16 日。属于论文、模型与集成代码更新，未核验同行评审。[论文](https://ahadjawaid.com/nat-paper)｜[项目](https://www.ahadjawaid.com/nat)｜[合并记录](https://github.com/huggingface/lerobot/pull/5416)｜[策略权重](https://huggingface.co/ahad-j/nat-vla-450m)。

NAT 用因果卷积编码/解码与多尺度有限标量量化，以 MSE 重建动作；训练语料约 **49k 小时、156 个数据集**，包含机器人、UMI、仿真和人手动作。配套 VLA 基于 LFM2-VL，以动作 token 交叉熵及 z-loss 训练，冻结原始 token embedding。默认 32 步动作、每组至多七维压成 14 个 token；前四个 token 已能解出前八步。它相对 FAST+、OAT/NAC 的区别在时间因果性：先产生可执行前缀，再继续生成；已执行动作的 token 还可约束下一段起点。更多动作维度会分组，当前流式路径有七维限制。[LeRobot 使用与约束](https://huggingface.co/docs/lerobot/main/en/nat_vla)

**作者论文报告**，统一四基准 VLA 的 token 执行平均成功率 **61.4%**，FAST+ 为 37.4%；加 flow expert 后分别为 73.6% 和 71.4%，说明 token 化尚未在所有任务上取代连续动作头。四个真机任务各十次，NAT 均值 **55%**、FAST+ 35%，但葡萄任务 NAT 仅 20%、FAST+ 70%。RTX 4090、batch 1、CUDA graphs 下，NAT 前八动作 **19.0 ms**、完整动作段 39.5 ms；LeRobot PR 报告首动作约 **40 ms**，两者是不同实现/测试口径。对 GR00T、π0.5、MolmoAct2 的 NAT 延迟估算只是解码步数计时，不能称它们已用 NAT 训练并取得相应成功率。

**值得精读表示和执行联合设计。** 当前已核验主分支实现、约 **2.16 GB** 策略文件、独立 tokenizer 配置/权重；旧 PR 正文仍写“权重未公开”，当前 Hub 文件已可见，不能照抄旧状态。完整原始混合数据包与全套训练链未核验；代码 Apache-2.0，权重为 LFM Open License。轻量验证先重放一小批动作，检查全段/前缀解码一致性、归一化和段间跳变，再用单个仿真任务做流式/非流式配对。文档提供 24 GB GPU 的梯度累积方案；无需先复现 49k 小时 tokenizer 训练。

## 3. Tesla Reality View：共享视觉特征，分出实时生成支路｜P1

**发布方：Tesla；架构说明署名 Elon Musk。FSD v15 上线公告为 11 月 21 日 19:24 UTC，补充架构说明为 22 日 11:02 UTC。** 属于官方产品发布和技术说明，没有随附论文或已核验同行评审。[Tesla 上线公告](https://x.com/Tesla/status/2124222447855743019)｜[原始架构说明](https://x.com/elonmusk/status/2124458557525397780)。本期新证据是后者，不能把“去年已存在内部世界模型”写成今天发布了完整新训练方法。

官方称车载可视化以近期 Universal Vision Encoder 特征为条件；同类特征进入约 3B 的驾驶动作模型，另分支进入约 **1B 的条件 mean-flow/扩散模型**。生成器对上一轮可视化加噪、再去噪得到当前视频，输出 **八帧、36 fps** 的短段；视觉条件更新为 18 Hz，计算分散到四个周期。训练损失、数据配方、相机几何监督与动作分支的梯度关系没有公开。它与 Genie 的交互生成、Cosmos 的合成数据和显式 3D 重建关注点不同：当前可核对的是感知条件下的车载生成界面，不足以确认持久三维状态或可用于策略训练的反事实模拟器。

**官方说明**使用半个 AI4 TRIP 加速引擎，并承认当前延迟较高；“约再降 35% 延迟”是拟采用的优化方向，尚无独立计时。36 fps 也不等于传感器到显示的端到端延迟。上线公告另称安全关键情形处理改善 25 倍，但未随附分母、场景分布和外部安全验证，不能把这一数字归功于显示生成器。今天的研究价值是提示我们审计共享表征的多用途，而不是从画面流畅度直接推出驾驶或机器人任务成功。

**值得读短说明并跟踪接口，暂不具备完整复现条件。** 未见本次车载模型代码、权重、训练数据或公开评测包；本轮没有车辆实测。轻量替代可在开源视频编码器上分出状态预测和小型视频生成头，用时间戳测各自延迟，检验遮挡目标、几何位置和罕见事件是否都正确；再干预生成支路，检查动作是否随之变化。只有受控干预才能区分“共同读取特征”和“控制真正利用生成结果”。

## 4. Hy4 正式权重：多模态 Agent 底座进入可检查阶段｜P1

**发布方：Tencent Hy 团队。11 月 20 日正式开放 Hy4、Hy4-FP8、Hy4-base；本轮核验的官方 Hub 更新为 03:05 UTC，不能用 10 月仓库创建时间替代本次发布日。** 属于官方模型与代码/权重发布，未核验同行评审。[官方仓库](https://github.com/Tencent-Hunyuan/Hy4)｜[模型卡](https://huggingface.co/tencent/Hy4)｜[FP8 文件](https://huggingface.co/tencent/Hy4-FP8/tree/main)。与八月 preview 区分：当前版新增视觉和更强长程工具工作流，并实际提供正式模型资产。

语言骨干 **770B 总参数、每 token 激活 49B**，另有 1.23B 视觉编码器及 3.3B DFly2 drafter。方法组合 Gated DSA、跨层稀疏索引复用 IndexCache、iHC 残差流与动态分辨率视觉接入；DFly2 复用稀疏 KV 和索引，降低长上下文投机解码开销。预训练、中期合成指令数据和后训练共同塑造能力，但完整损失权重、数据与奖励配方未公开。相对 DeepSeek/GLM 的稀疏注意力路线，价值在开放的多模态和 Agent 工程组合，不宜将所有提升归给单个结构。

**官方报告** Base 在 SuperGPQA 为 **62.7**，其对照 DeepSeek-V4-Pro-Base 为 54.8；Hy4 Base 的 MMMU-Pro 为 59.6。这些是指定 few-shot 设置，不能移作 instruct Agent 成功率。团队还报告与 Hyra 2.0 harness 联合完成小模型基础设施优化与训练，但没有本轮独立核验的完整轨迹和等预算对照，尚不能称为自主递归自进化的证明。官方也承认高难研究数学、长程编码及模型自改进与顶级闭源系统存在差距。

**值得读架构和限制，部署投入需按实际文件估算。** 本轮枚举得到 BF16 instruct **245 个分片、约 1.549 TB**，FP8 **245 个分片、约 786.3 GB**；已核验文件存在，未下载加载。激活参数少不意味着只需存储 49B 权重，长上下文还占 KV。官方提供推理/微调入口，但完整预训练数据未开放；许可为 **Tencent Hy License 1.0**，并非 Apache-2.0。轻量验证可在获准 API 或现有集群上取十个视频/工具任务，对齐 harness、推理预算与帧数；若验证结构机制，先在小模型上比较稀疏索引复用和 drafter 接受率，不必重训 770B。

## 5. RoboColosseum 新榜单：相对领先仍伴随较低完整完成率｜P1

**基准作者：Tan Sang Nguyen、Yi Ru Wang、Shailesh Shailesh、Jiafei Duan 等；NUS MAGIC、Hugging Face、新加坡 Embodied AI Centre、BitRobot 等团队。** 原论文为 11 月 2 日预印本；本次依据是 **11 月 20 日 19:46 UTC 的 SO-101 新评级及当晚作者公告**。GPT-6.2 已在 18 日晨报介绍，本期因新增外部机器人评测重访，不能称新模型首发。[论文](https://arxiv.org/abs/2611.02497)｜[官方榜单](https://robocolosseum.ai/leaderboard)｜[评级原始数据](https://robocolosseum.ai/api/leaderboard?robot=so101&track=open)｜[作者公告](https://x.com/DJiafei/status/2123925760281067567)。

Open Track 在同一机器人、场景和新指令下盲比两个系统，汇总偏好、平局与不确定性；Fine-tune Track 则固定每任务 100 个示范，比较适配后的表现。它是测量协议与评级模型，不提供新的策略训练目标。相对固定任务成功率基准，优势是扩大真实环境分布并保留失败记录；但不同任务、机器人和模型接入服务仍会影响结果，不能跨本体直接比较评级。

**本轮读取基准方当前 API**：GPT-6.2 Astra 的 SO-101 评级约 **1984，后验标准差 96，122 次比较**；Claude Fable 5.2 约 1803、标准差 91。两者公布的区间重叠，没有据此宣称统计显著领先。Astra 对应记录有 **27 次完整成功、successRate 字段 22.13%**，所以 1984 是相对表现评级，不是接近 100% 的执行可靠性。样本不是固定同分布任务集，模型服务身份与完整 harness 本轮未独立审计；这些数字属于基准作者对外部模型的测量，并非多团队复现。

**值得精读协议和不确定性。** 论文、接口与 Hugging Face 组织已可访问；项目承诺公开全部运行记录，但本轮只核验榜单数据与组织入口，未逐条验证全量视频、数据完整性或模型权重。轻量验证先抽二十对公开轨迹，隐藏模型名重新标完整成功和偏好，再做按站点/任务重采样，观察排名稳定性；需要运行模型时，先锁定同一机器人、接入服务、调用预算和重置协议。不要把盲偏好、部分进度和绝对成功混成一个指标。

## 6. IsaacSwim：将水动力接入可批量训练的仿真链｜P2

**作者：Danyi Chen，CITATION 未列机构。11 月 20 日 01:49 UTC 作者在 NVIDIA 论坛发布公告；0.1.1 代码实际提交于 19 日 16:55 UTC，早于本期窗口，不能写成今日首开源。** 属于社区仿真软件研究 beta，非 NVIDIA 官方模型发布，未核验同行评审。[作者公告](https://forums.developer.nvidia.com/t/isaacswim-an-underwater-robotics-add-on-for-isaac-sim-and-isaac-lab/389664)｜[代码](https://github.com/danyichen/IsaacSwim)｜[文档](https://danyichen.github.io/IsaacSwim/)｜[评测协议](https://github.com/danyichen/IsaacSwim/blob/main/docs/benchmarks.md)。它补足 Isaac 机器人仿真中水下力、浮力和传感器的接入问题，拓宽 generative simulation / real-to-sim 的物理任务范围。

系统以 torch/NVIDIA Warp 实现 MuJoCo 椭球流体模型，加入网格排水浮力、水流、推进器和海洋传感器；可接入批量 Isaac Lab 环境、任务脚本、HDF5 示范和 RL demo。它是仿真组件，未提出新的通用策略训练目标，也不是 CFD 求解器。相对 Stonefish/HoloOcean，价值在将水下任务纳入已有 GPU 机器人训练栈，而非自动获得更真实的流体。

**作者报告**在同一 RTX 4070/i7-13700F 上比较速度和两秒开环预测误差：单艇 Stonefish 更快，较大批量中 IsaacSwim 扩展更好。公开图中手动控制组位置误差约 **18 cm**，Stonefish 23 cm、HoloOcean 81 cm；不同原生模型、传感器负载和启动计时口径并不完全一致。协议明确没有拟合水槽数据，也没有建模缆绳和电池电压下降，因此不能把排序扩大到任意真实水下任务。本轮没有重跑其模拟器或训练策略。

**适合按需阅读与低成本审计。** 核验了 Apache-2.0 源码、任务工具、文档与评测图；未确认完整基准原始输出及可直接复用的训练策略权重。稳定目标为 Isaac Sim 5.1 / Isaac Lab 2.3，6.2/3.0 仍属研究预览。轻量验证先做静水浮力平衡、无推力阻力衰减和定推力加速，再固定一个真实轨迹片段比较两秒预测；通过后再做小批量 RL。物理组件验收应先于视觉场景和大规模训练。

## 今日研究地图

| 问题分类 | 今日映射与近期趋势 | 尚未解决的 gap | 可形成论文的机会 |
|---|---|---|---|
| 持久空间与生成界面 | Tesla 将共享视觉特征分成动作和视频支路 | 画面合理、三维状态正确、被动作利用仍未连通 | 同一表征的状态、渲染、控制三路干预审计 |
| 动作表示与在线执行 | NAT 让因果 token 前缀直接进入执行链 | 动作压缩误差、首动作延迟与控制收益缺少统一预算 | 同策略下测前缀长度、段间跳变和限时成功曲线 |
| 机器人 Agent 与经验 | Waddle 组合云端推理、本地策略、跨尝试上下文 | 单模型能力、记忆学习与调用次数贡献混杂 | 重置协议×记忆×预算的因子实验与留出任务迁移 |
| 跨本体评估 | RoboColosseum 新榜单，Robocurve 公布系统记录 | 评级、平均进度、完整成功和成本容易被混用 | 双评分与站点重采样，测排名与可靠性的分离 |
| 多模态基础模型 | Hy4 开放权重与稀疏推理工程 | 视觉问答、长程工具能力和研究自改进未共同验收 | 对齐 harness/帧数/计算量，建立可审计的科研 Agent 任务 |
| 物理环境与 real-to-sim | IsaacSwim 扩展水下批量仿真 | 近似水动力、真实参数与策略迁移仍有误差 | 系统辨识与跨求解器留出轨迹测试，连接到策略退化 |

近期共同趋势是把能力装进可执行系统和持续评测。真正的空缺是**条件与预算可追溯的因果证据**：改善来自模型、表征、工具、记忆还是更多尝试，必须分别验收。持续研究地图已保留此前几何、材料、视频表征、人类数据与自进化分支，本期新增上述连接，不删除历史证据状态。

## 今日研究机会与轻量验证

- **先做公开数据的评测审计**：Waddle 的原始 120 条记录可重算进度与完整完成；本轮已完成计数核对，尚未人工复核全部视频。下一步从六任务各抽五次，独立重标并报告分歧，尤其比较早期与后期尝试，检查跨尝试上下文是否改变结果。
- **动作接口的最小实验**：一批固定动作和一个仿真任务，比较 NAT 前缀/全段、流式开/关、延迟 0/50/100 ms；同时记录首动作时延、轨迹误差、段间不连续与限时成功。先验证执行语义，再投入预训练。
- **共享世界表征的干预测试**：十段有遮挡和罕见事件的视频，固定编码器，分别评估状态、生成与动作；打乱生成支路条件，查看视频质量和动作是否一同退化。没有动作干预收益时，结论应停留在共享特征的多任务读取。
- **经验与自进化的公平比较**：固定工具库与二十个任务，用清空上下文、保留任务内上下文、保留跨任务经验三组，在同墙钟和同调用预算下比较 rescues/regressions；最终经验冻结后再测试未见任务。将 Waddle 的系统路线与 SkillPlumber 等经验演化问题连接，但不预设二者已有相同机制。
- **仿真可信度先于规模**：用单个水下刚体和一段留出真实轨迹，改变阻力、浮力、时间步和推进器参数，测两秒状态误差及策略性能退化；小场景也能研究哪些物理误差会改变决策。

## 证据状态与可复现性

- **外部测量可见**：Waddle 的第三方榜单、120 条结构化记录及视频入口；RoboColosseum 的评级 API 和模型比较。它们独立于模型开发方，但评测预算、会话和接入条件仍需审计，不能升级为广泛独立复现。
- **代码/文件实际可见**：NAT 主分支、策略和 tokenizer 文件；Hy4 三套模型文件清单；IsaacSwim 源码和评测协议。文件存在、可加载、推理正确、闭环成功是四个不同状态，本轮只完成前者及静态/记录核查。
- **官方说明为主**：Tesla 架构、资源与安全改善主张尚缺公开代码/数据和独立计时；Hy4 的实验、NAT 的论文实验、IsaacSwim 的性能均为作者/官方报告。
- **尚未执行**：大权重下载、从头训练、付费 API 测试、真机与车辆实验、完整仿真复现。NAT 的完整混合数据准备、Hy4 完整训练配方、Waddle 核心服务及 Tesla 模型工件仍未核验开放。不要将本期公开文件与日志审计表述成实验复现。

今天先读 Waddle 的评测约束与 NAT 的因果解码，再选一个固定任务测试记忆重置或动作流式执行。最先值得验证的不是再提高一个榜单数字，而是**在同预算下，改进是否仍然存在，并且能提高完整任务成功率**。
