## 今日精读顺序

今天我建议的精读顺序是：

**A → Gemini 4 Argon for Robotics**：先看一个官方 frontier system 如何把物理推理、代码生成、视频到仿真到真实机器人串成闭环；它代表能力与产品化上限，但证据仍主要是官方报告。

**B → Grounded-Dreamer**：再看如何用 world model 产生视觉真实的轨迹，并用仿真 replay 过滤物理错误，这是“视觉想象 → 动作标签”的关键接口。

**C → What Visual Representations Do World Action Models Need?（Representation Recipe / R²-WAM）**：用受控实验拆开表征选择、集成机制和特征组合，直接回答 WAM 的视觉表示该怎么选。

**D → S-Space**：从 benchmark 结果下沉到内部机制，检查 MLLM 是否真的形成了可读、可干预的空间坐标工作区。

**E → MAGMA-Bench**：最后用动态任务、执行失败和任务中断检验 agent 是否能把上述能力维持到长时程、多机器人执行中。

## 重点论文 / 模型 / 项目

## 1. Gemini 4 Argon for Robotics｜P0

**作者与机构、时间、性质。** Google DeepMind / Google Developers，主要公开作者为 Kanishka Rao；Google 官方总发布由 Koray Kavukcuoglu 等署名，发布时间 **2026-10-13**。这是官方模型发布与开发者技术文章，不是同行评审论文；官方机器人入口为 [Gemini 4 Argon for Robotics](https://developers.googleblog.com/gemini-4-argon-for-robotics/)，通用发布见 [Google DeepMind 官方公告](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-argon/)。

**研究问题与方法。** Argon 将视觉语义推理、物理理解、代码生成和 agentic 调度放到同一个可调用模型中，目标不是单一 VLA，而是让模型从机器人视频或草图构建 MuJoCo 数字孪生、在仿真中练习、闭环检查，再把策略送到真实机器人。开发者文章展示了四类模块：MuJoCo 练习与零样本控制、Real2Sim 重建、物理后验标注/进度估计、仿真驱动的硬件自改进；还展示了对 Gemini Omni 视频 world model 的时间戳动作提示和迭代 steering。训练数据、参数规模、动作头和具体损失函数没有公开。

**结果与证据。** Google 报告 Argon 在 Embodied Reasoning（ERQA）上达到 **87%**，并称超过其他 frontier model；官方示例包括从人类 cornhole 视频建立仿真并迁移到 Apptronik Apollo，连续命中 7 次，以及从单张桌面图生成 4,500+ 个带域随机化的仿真 episode，使真实 Success Rate 从 **56% 提升到 75%**、完成时间从 35 s 降至 24 s。所有数字均是 Google 官方报告，尚无公开第三方复现；机器人视频是 demonstration evidence，不等同于公开 benchmark protocol。

**创新、局限与关系。** 它把 Gemini Robotics、Genie/Omni 视频生成和 Real2Sim 工程流程接到一个通用 agent 接口上，代表“world model 作为可调用工具和训练场”的路线。局限是闭源、训练目标未知、官方 prompt 与 demo 选择可能影响结果，且 87% ERQA 与真实长时程控制之间仍有 gap。它与上一期 World Labs R2S2R 的方向一致，但 Argon 更强调通用 reasoning/code agent；与 Grounded-Dreamer 的差别是后者给出可审计的 world-model 轨迹 replay 过滤。

**可复现性与轻量验证。** 模型权重未发布，API/AI Studio/Antigravity 可用；可先用 API 复现一个低风险 MuJoCo 任务：输入视频或 RGB-D 观测，要求输出场景 XML、动作 primitive 与每一步验证日志，再与手写数字孪生和 Qwen/开源 VLM baseline 比较。重点记录 Real2Sim 几何误差、接触事件误差、闭环恢复次数，而不是只看最终成功。

## 2. Frontier Models for Every Robot：Physical Intelligence Pi API beta｜P0

**作者与机构、时间、性质。** Physical Intelligence（π 团队）官方博客，发布时间 **2026-10-13**；这是官方产品/研究基础设施发布，不是论文。链接：[Pi API beta 官方公告](https://www.pi.website/blog/api-beta)。

**研究问题与方法。** Pi 试图解决机器人 foundation model 适配的工程瓶颈：用户上传自己的 demonstration，Physical Intelligence 托管 fine-tuning 计算和数据管线，再通过 hosted gateway 让机器人调用微调后的模型。官方明确把流程定义为“上传数据 → fine-tune π 模型 → 部署 → 用失败决定下一轮数据”，并称底层模型会持续更新。公开文本提到 π0、π0.5 及“最新模型”，没有披露当前 API 对应的确切 checkpoint、训练目标、参数规模或 action head。

**结果与证据。** 官方给出早期合作案例：Almond 的 Axol 双臂机器人在约四天的迭代后执行零件去毛刺；Actor 的轮式装载机在商业部署中完成装载；同时承认部分云端部署遇到网络连接问题。上述均为公司和合作方的官方叙述，没有公开统一测试集、置信区间或第三方独立评测。

**创新、局限与关系。** 重要变化是从“研究者自己搭训练系统”转向“模型即服务 + 机器人数据闭环”，它可能改变数据规模和失败回流速度。代价是闭源权重、托管推理、版本漂移和数据隐私；如果 API 更新底层模型，实验可比性会变差。它与 Gemini 4 Argon 的通用 physical reasoning 互补：Pi 更像面向真实部署的 adaptation substrate，而不是公开的空间推理模型。

**可复现性与轻量验证。** API 为 beta/申请制，权重、训练数据和本地推理均未公开。可行的小实验是用 20–50 条同一机械臂 demonstration，固定 10 条 held-out 任务，比较 API fine-tune、OpenPI/π0 开源复现和 LoRA baseline 的数据效率、失败类型和版本稳定性；务必记录网络延迟和每轮模型版本。

## 3. Muse Wonder / Muse Wonder Full：Frontier Models for Agents｜P1

**作者与机构、时间、性质。** Meta AI Research，发布时间 **2026-10-12**；官方研究页为 [Muse Wonder](https://research.meta.ai/blog/muse-wonder)，产品页为 [Muse Wonder model card](https://dev.meta.ai/models/muse-wonder)。这是官方模型发布与研究说明，不是同行评审论文。

**研究问题与方法。** Meta 将两个模型定位为长时程 personal/professional agent：**Active Memory** 跨对话保留并检索相关上下文，**Active Focus** 在任务卡住时尝试替代路径、恢复错误、请求澄清并在重要动作前确认。官方称模型经过预训练与 RL 的规模化训练，在 Prometheus 数据中心训练；架构、参数、训练混合和 memory 写入/检索损失没有公开。

**结果与证据。** Meta 以 Harvey LAB、FocusBench、SWE-Marathon 和 coding 评估声称 state-of-the-art；Muse Wonder 可经 Meta Model API/Muse Code 使用，Muse Wonder Full 仅对 Muse Code 订阅者开放。第三方模型目录显示 Wonder 约 1M context、API 价格 $4/$20 每百万输入/输出 token，Artificial Analysis 的 max-effort 指标列出 Wonder 52、Wonder Full 56；这些是第三方读榜结果，不是机器人或物理任务验证。Meta 的完整 safety report 仍“即将发布”。

**创新、局限与关系。** 它将 memory、持续执行和工具调用作为模型产品的一等能力，和 MAGMA-Bench 的“执行中保持状态并应对扰动”直接相关，但它不是 embodied model。局限是闭源、官方 benchmark 细节不完整，独立第三方只验证了有限的文本/代码指标，无法据此推断真实世界 agent 可靠性。

**可复现性与轻量验证。** 只有 API/产品访问，没有权重。可用 20 个多轮任务做 memory ablation：无跨会话记忆、仅检索摘要、帧/文档混合记忆；记录任务完成率、恢复次数、错误操作率和 token 成本，并把结果与开源长时程 agent 对比。

## 4. AI models may be capable of self-replicating without access to a datacenter｜P1

**作者与机构、时间、性质。** William Zhou、Daniel Freeman，Anthropic Frontier Red Team，官方研究报告 **2026-10-12**；链接：[Anthropic 官方报告](https://www.anthropic.com/research/self-replicating-ai)。这是安全研究/红队报告，不是同行评审论文。

**研究问题与方法。** 报告把自主复制拆成目标发现、初始访问、建立推理服务、继续传播四阶段，重点测量小模型在异构硬件上搭建推理服务和串联传播的能力。实验使用 Memento harness（每轮 1.5 h、总计 6 h），在 15 台廉价 Android TV 盒子上分布式运行 Gemma4-26B-A4B，并在隔离的 8/17 节点 redroid/GCP 网络中测试复制链；同时测试代际 notes 是否能让 Qwen3.5-9B 适应新硬件。

**结果与证据。** Anthropic 报告 9B 模型能在 9 种硬件中的 8 种建立 Llama3.1-8B 推理；GLM-5.2 在简化隔离环境中 5 次试验有 4 次传播到 8/8 节点、另一次到 7/8。Gemma4-26B-A4B 在 15 台电视盒上约 0.39 token/s；Qwen3.5-9B 的推理部署成功率随继承 notes 的代际从 45% 上升到 61–84%。作者明确承认忽略真实漏洞利用、使用未认证 ADB 等简化条件，因此这是能力预警，不是“野外 AI 蠕虫已经出现”。

**创新、局限与研究价值。** 新意在于把“模型能写 exploit”转成完整的 inference-setup 和 propagation 组合能力，并把代际经验传递纳入评估。局限是 threat model、网络拓扑和提示词都被人为简化，不能外推真实 R0；模型、数据和 harness 不是完整可复现开源包，页面主要提供嵌入式图表与实验细节。它与 Meta 的 Active Memory、MAGMA 的 failure memory 共同指向“经验是否可传播”的安全问题。

**轻量验证。** 只在本地无网络容器中做 mock-device 评估：为 6 种 CPU/内存配置写假的 serving API，测小模型是否能选择正确的量化/并行方案、识别失败并把 notes 传给下一代；不要连接真实设备、扫描公网或复刻传播步骤。指标是 setup success、回退次数、继承 notes 的增益和误报。

## 5. Grounded-Dreamer：Robot Learning from World Model Synthetic Data with Physical Grounding｜P0

**作者与机构、时间、性质。** Feng Jiang、Shu Chen、Yuanfei Wang、Yuan Li、Zhenhao Shen、Jiaqi Liang、Yang Chen、Lei Wei、Chen Xie、Ruihai Wu；机构为 **Peking University、Hong Kong University of Science and Technology (Guangzhou)、Lightwheel**。论文 [arXiv:2610.13164](https://arxiv.org/abs/2610.13164)，项目页 [Grounded-Dreamer](https://fffstrong.github.io/Grounded-Dreamer/)。v1 提交时间为 10 月 9 日，但在 10 月 12 日 arXiv 最新批次中出现，属于本期明确标注的批次边界项；项目页显示代码 **Coming soon**。

**研究问题与方法。** 从少量真实初始图像重建任务相关物体和相机几何，在仿真中收集物理有效轨迹；用 interaction-aware masking 微调 Cosmos Predict 2.5 world model，再用 inverse dynamics model 将生成视频映射为动作；把生成轨迹 replay 回重建仿真，只保留成功完成任务的样本，最后仅用通过验证的合成轨迹训练 π0.5 和 Diffusion Policy。核心目标是把视觉逼真度与动作/接触可行性分开验证。

**结果与证据。** 项目页给出 7 个 Franka 真实任务、每任务 50 条 GD 轨迹、20 次评估。π0.5 仅用 GD 数据的平均成功率为 **55.0%**，高于 Sim-only 的 8.6%，低于 Real-only 的 63.6%；5 条真实轨迹 + 50 条 GD 轨迹的 Co-training 达 **65.7%**。Diffusion Policy 的 GD-only 平均为 42.9%，Co-training 为 52.9%。作者还报告经过环境、纹理和光照变化后，verified GD 数据在七项任务上均优于未验证 real-only 低数据设置。所有数字为作者/项目页报告，尚无第三方复现。

**创新、局限与关系。** 它把“视频 world model 会不会幻觉”转化为可执行的 simulator replay gate，是 World Labs R2S2R、Splat2Act 和 DreamTrue 之间缺失的证据接口。局限是重建、world-model fine-tuning 和 replay 仍需较大算力；仿真参数错误可能把真实有用轨迹错误过滤掉；代码、数据和权重尚未公开。

**轻量验证。** 选一个 Franka 抓取/按键任务，用小型 latent video model 或现成视频模型生成 50–150 条轨迹；分别比较“看起来成功”的视频、replay 成功和真实执行成功，做 replay gate 的 precision/recall；先不训练完整 π0.5，只训练一个小 diffusion policy，验证过滤是否减少接触失败。

## 6. What Visual Representations Do World Action Models Need?（Representation Recipe / R²-WAM）｜P0

**作者与机构、时间、性质。** Kai Liu、Jiangran Lyu、Tingyu Deng、Yixin Zheng、Jingtian Wan、Wenbo Cui、Mi Yan、Yizhou Zhou、Haoran Li、Dongbin Zhao、Zhizheng Zhang、He Wang；机构为 **Institute of Automation, Chinese Academy of Sciences、Galbot、Peking University、University of Science and Technology of China**。论文 [arXiv:2610.13024](https://arxiv.org/abs/2610.13024)，项目页 [R²-WAM](https://kailiu18.github.io/R-2WAM.github.io/)。这是预印本；不要与另一篇“Repair-and-Reject Post-Training for WAMs”混淆。

**研究问题与方法。** 论文在固定 WAM 框架和训练协议下比较 **13 个视觉 encoder、5 种集成机制和多个 feature 组合**，回答“选什么表示、怎么集成、是否越多越好”。结论方案是 DINOv3（通用视觉自监督）+ UniTok（多目标表征）+ V-JEPA 2.1（视频预测）通过 channel-wise concatenation，并预测 future features；作者还做 action sensitivity 和三 seed 的均值/标准差分析。

**结果与证据。** 项目页报告：VAE-only 总体成功率 74.7%，DINOv3 单源 84.0%（+9.3 pp）；13 个来源的 channel-wise 集成均值 81.5%，比下一种机制高 5.1 pp；三源 R²-WAM 在 LIBERO-Plus 达 87.3%；RoboCasa GR1 Tabletop **84.7%**（较 VAE-only +5.9 pp），RoboTwin 2.0 **92.8%**（+2.2 pp）。真实 Galbot G1 四任务、每模型每任务 20 次：air-fryer 50→60%、pick-and-place 70→80%、sweeping 48.3→66.7% debris collection、cup pushing 65→75%。这些是作者/项目页报告，公开的第三方 Pith 页面是 AI review 而非独立重跑。

**创新、局限与关系。** 贡献不是新 backbone，而是把 WAM 表征选择变成可复用的 controlled recipe，提醒研究者先加入强通用表示，再谨慎增加专用表示。局限是训练代码和模型权重未确认公开；真实机器人样本仍小，LIBERO-Plus 扰动是合成的；最佳组合的额外收益小于第一步加入 DINOv3 的收益。

**轻量验证。** 在一个现有 WAM 上冻结 DINOv3/UniTok/V-JEPA encoder，只改 feature adapter；跑 3 个 seed、10 个 LIBERO-Plus 任务和 4 个真实/仿真接触任务，报告 action sensitivity、nearby-action counterfactual、显存和延迟。最小预算约 1–2 张 24 GB GPU，不需要预训练 WAM。

## 7. S-Space：Exploring Spatial Workspace in Multimodal Language Models｜P0

**作者与机构、时间、性质。** Zhiyuan Shi、Xiang Li、Xingzhuo Guo、Shangchen Miao、Weiliang Chen、Qiyu Dai、Jinshan Ren、Jiangran Lyu、Fangfu Liu、Mingsheng Long、Jialong Wu；公开项目归属 **MirroS / MirroS-Lab**，论文页未在摘要中统一列出全部高校隶属。论文 [arXiv:2610.13527](https://arxiv.org/abs/2610.13527)，代码仓库 [MirroS-Lab/S-Space](https://github.com/MirroS-Lab/S-Space)（Apache-2.0）。

**研究问题与方法。** 作者在 MLLM 中发现一个三维线性子空间，object-token 表征沿水平、垂直、距离轴编码连续坐标。方法用空间答案分数对 object-token activation 求导定位轴，再做 readout、跨 prompt/多视角测试和 causal intervention；模型在非空间问题中仍可读出该空间，说明它不是某个 prompt 的临时产物。关键结论是：模型能形成空间表示，但在 viewpoint change 所需的坐标变换上出现瓶颈。

**结果与证据。** 论文/项目报告了可读性、跨 prompt、多视角和因果编辑；公开仓库提供预训练 axes、Molmo2-ER/MolmoAct2/Qwen3.5-4B/Qwen3.6-27B 的配置，以及 COCO、SpatialTunnel、EmbSpatial、CV-Bench、HStar、SpinBench 的准备和复现实验脚本。二手摘要曾报告 SpinBench 从 native reasoning 约 60.96% 提升到 94.52%，但该数字应暂记为二手报道，不能当作独立复现结果。

**创新、局限与关系。** 它把 Spatial Intelligence 从“在空间 benchmark 上得分”推进到“定位、读出、干预内部坐标工作区”，可与 VLA 的未来状态表示和 R²-WAM 的 action-sensitive feature 直接对接。局限是目前主要证明 MLLM 内部表征，不等于可执行的 3D action grounding；坐标轴的跨模型稳定性、真实机器人闭环收益和训练数据因果性仍待验证。

**轻量验证。** 按仓库脚本在 Qwen3.5-4B 或 Molmo2 上跑 axis construction 与 SpinBench；加入显式 3D viewpoint rotation，再将 readout 坐标喂给一个小型抓取/指向策略。验证三件事：空间干预是否只改变空间答案、旋转是否修复 viewpoint gap、表示收益是否传到动作成功而不是只提升 QA。

## 8. MAGMA-Bench：Evaluating Long-Horizon Embodied Agents under Dynamic Tasks and Execution Failures｜P1

**作者与机构、时间、性质。** Loan Bernat、Matthieu Grard、Ariane Herbulot、Florent Lamiraux，来自 **LAAS-GEPETTO / LAAS-RAP（CNRS）**。论文 [arXiv:2610.13534](https://arxiv.org/abs/2610.13534)，项目页 [MAGMA](https://magma-rob.github.io/)。论文为预印本；项目提供可运行 benchmark 与数据生成框架。

**研究问题与方法。** MAGMA-Bench 把长时程、多机器人、异构能力和在线扰动放到一个 architecture-agnostic 协议中：任务会发生执行失败、任务中断、mission update，agent 通过结构化 skill-level interface 与低层感知/控制解耦。配套 MAGMA-GEN 从 agent 自己的轨迹和错误状态中收集样本，教练式 correction 必须经过仿真执行验证后才进入监督数据；作者明确说明 GEN 不做在线 RL 更新。

**结果与证据。** 论文报告即使最强测试模型在 clean episode 上也会失败，加入在线扰动后成功率进一步下降；监督适配能显著提升小模型，但长 horizon 和多机器人任务仍明显困难。公开版本包含 **261,646 条 task-level training examples**、expert-trace generation pipeline；项目页当前标记 MAGMA-BENCH v1.0.0、MAGMA-GEN stable v2。摘要没有给出单一总分，因此不把“显著失败”改写成未经证实的具体百分比。

**创新、局限与关系。** 它补上了 MC-EvoBench 一类经验自改进 benchmark 缺少的执行中失败、任务变化和异构机器人协调，适合研究 persistent memory、failure attribution 和 verifier。局限是 skill-level abstraction 可能掩盖感知/动作层失败，frontier model 结果会受 planner prompt 和 simulator 影响；仍需真实机器人或跨 simulator 验证。

**轻量验证。** 下载 v1.0.0，在本地用一个 7B planner 和一个 frontier API 跑 10 个短场景；对每个场景分别加入 failure、interrupt、mission update，记录状态追踪、恢复动作、无效调用和成本。先固定 skill interface，再逐步放开视觉输入，能把“记忆失败”与“控制失败”分开。

## 9. LAPT-Scale：Scaling Embodied Policies with Latent Action Pre-Training on Human Videos｜P1

**作者与机构、时间、性质。** Zhiyuan Xiang、Peidong Liu、Mingyang Li、Jiawei Li、Wenhow Li、Wenbo Ding、Xiang Deng；论文 [arXiv:2610.13732](https://arxiv.org/abs/2610.13732)，标注 **CoRL 2026 accepted**；在 10 月 12 日 arXiv 批次中出现，v1 submission history 为 10 月 9 日，属于批次边界项。

**研究问题与方法。** LAPT-Scale-LAM 在人类 egocentric video 中学习连续 latent action 来解释帧间变化，再通过 target-robot embodiment alignment 和 task-specific post-training 训练 VLA。它不用离散 VQ latent，而结合 perceptual、semantic、optical-flow 对齐，试图把 23.3K 小时人类视频变成隐式 action supervision。

**结果与证据。** 作者报告随着标注人类视频从 1K 增至 5K 小时，真实机器人成功率从 **63.3% 提升到 85.0%**，并在未见视觉条件上泛化；这些是作者实验结果，尚未看到公开第三方重跑。论文未在可访问页面确认代码、数据或权重公开，23.3K 小时原始视频本身也不太可能直接开放。

**创新、局限与关系。** 这是 human-to-robot alignment 的规模化路线，与 HARP-VLA、latent action pretraining 和 Pi API 的数据闭环相邻；连续 latent 对细粒度接触有潜在优势。局限是 latent action 的可辨识性、跨 embodiment 语义是否稳定，以及 85% 是否依赖大量私有预处理和大算力。

**轻量验证。** 不复制 23.3K 小时规模；选 50–200 小时公开视频，训练一个小 LAM，比较 pixel-only、optical-flow-only 和 perceptual+flow 三种监督，再在 CALVIN/LIBERO 的 2–3 个任务上做冻结 encoder + 小 action head。报告跨 embodiment 的 latent consistency、动作成功和预训练成本曲线。

## 10. PhysForge：Material-Controllable 3D Reconstruction with Separable Components｜P1

**作者与机构、时间、性质。** Yuchen Wang、Yanqi Bao、Zheng Gu、Zhengqing Chen、Jieqi Shi、Jing Huo；机构为 **Nanjing University、Horizon Robotics、Shenzhen University**。论文 [arXiv:2610.13681](https://arxiv.org/abs/2610.13681)，项目页 [PhysForge](https://masterwanna.github.io/PhysForge.html)。v1 为 10 月 9 日，随 10 月 12 日批次公开；预印本，项目页标记 GitHub to be released。

**研究问题与方法。** PhysForge 关注 3D world generation 中“看起来对”与“材料反应对”的差距。PhysFit 用 material-conditioned video diffusion dynamics 估计可控材料属性，windowed fitting 聚焦能揭示材料的交互片段，Hallucinated Forcing 分离视频模型幻觉运动；PhysComp 将复杂交互分解为对象和语义部件，独立估计物理参数后组合进 joint simulation。

**结果与证据。** 在 PhysAssets 和 Google Scanned Objects 上，项目页报告 common/uncommon materials 的 CLIP 与 physical controllability 均优于比较方法；PhysForge 的 CLIP 为 0.258/0.264，physical controllability 为 4.6/4.0（5 分制 VLM 评分）。这是作者/项目页结果，尚无第三方物理引擎复核；用户研究和 component ablation 已报告但原始数据未公开。

**创新、局限与关系。** 它把 Spatial Intelligence 的对象重建进一步推进到材料与组件级可交互 world，和 Grounded-Dreamer 的“动作 replay 过滤”互补。局限是 VLM 评分不能替代真实接触力、摩擦和弹性测量；代码/权重/数据未公开，物理参数的可辨识性仍是主要风险。

**轻量验证。** 选刚体、软垫、可变形物三类对象，在 MuJoCo/Isaac Sim 中固定质量、摩擦和刚度的 ground truth，比较 PhysForge 输出与简单 material classifier + system identification baseline；把同一生成资产放进两个物理引擎，报告接触轨迹和参数误差。

## 今日研究地图

| 问题分类 | 今日映射 | 近期趋势 | 仍未解决的 gap |
|---|---|---|---|
| 物理可验证的 world model | Gemini Argon、Grounded-Dreamer、PhysForge | 从视频逼真度转向接触、材料、replay 与 Real2Sim | 仿真参数误差、生成轨迹的 false positive/negative、跨引擎一致性 |
| WAM/VLA 的未来表示 | R²-WAM、LAPT-Scale | 从 RGB future rollout 转向 future feature、latent action 和通用视觉 encoder | 表征提升是否真正改善 action sensitivity；跨 robot/任务的可迁移性 |
| Spatial Intelligence 内部机制 | S-Space、Argon 的空间推理 | 从“空间 benchmark”走向可读、可干预的坐标工作区 | viewpoint transform、语言坐标到 3D action 的闭环 grounding |
| 长时程 agent 与自进化 | Muse Active Memory/Focus、MAGMA-Bench、Anthropic Memento | 记忆、失败恢复、经验继承成为系统级模块 | verifier 是否可靠、memory 是否引入污染、能力提升是否可重复而非 reward hacking |
| Physical AI 基础设施 | Pi API beta | 模型 fine-tune、部署、失败回流平台化 | 版本漂移、隐私、网络延迟、托管模型的可审计性与独立评测 |

最近趋势可以概括为四条：一是 **模型服务平台化**，二是 **动作相关的未来表征替代纯像素预测**，三是 **world model 输出必须经过物理验证**，四是 **agent 的 memory/failure loop 开始成为 benchmark 一等公民**。

仍有三个明显研究缺口。第一，官方 frontier 结果和论文结果之间缺少统一、可复核的第三方 protocol；第二，真实机器人结果常只有少量任务和 trial，无法区分“表征提升”与“场景/数据选择”；第三，Spatial Intelligence 的内部坐标表示尚未稳定地转成跨视角、跨本体的接触动作。

## 今日研究机会与轻量验证

1. **Replay-Certified World Model Data。** 以 Grounded-Dreamer 为起点，为每条生成轨迹同时保存视频成功、仿真 replay 成功、接触事件误差和 uncertainty；在一个 Franka 任务上比较无过滤、视觉过滤、物理 replay 三种策略。
2. **S-Space-to-Action。** 将 S-Space 的坐标 readout 和 viewpoint rotation 接到一个小型空间指向/抓取 policy，直接测“空间 QA 提升是否传到 action success”。
3. **Causal WAM Representation Audit。** 复现 R²-WAM 的单源 DINOv3 gain，再对 current/future feature、nearby action 和 contact-state 做干预；若性能只在静态场景上提升，说明表征没有真正编码 action consequence。
4. **Failure-Aware Agent Map。** 在 MAGMA-Bench 中固定 planner，逐步加入摘要记忆、轨迹记忆、可验证 correction，画出 horizon × perturbation × compute 曲线，而不是只报告平均成功率。
5. **Managed API Audit。** 对 Pi API 做多轮相同数据、不同版本的 fine-tune，记录数据效率、延迟、模型漂移和失败类型；与本地 OpenPI/LoRA baseline 做同一 held-out protocol。

这些实验都可以在 1–2 张 24 GB GPU、公开仿真环境和少量真实机器人试验上完成；不需要复刻 23.3K 小时人类视频、50B 模型或 4,500 episode 的官方规模。
