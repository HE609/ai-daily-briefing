# Research daily website

This repository is the user's existing GitHub Pages research-daily site at
https://he609.github.io/ai-daily-briefing/ . The user has authorized daily
report publication and pushes to `main` in `HE609/ai-daily-briefing`.

The parent workspace contains the completed Chinese research reports. Preserve
the research scope, source coverage, deduplication and evidence requirements of
the existing scheduled research task. Use Asia/Shanghai for reporting dates.
Do not invent missing historical reports. Old evidence states are historical,
not claims that a resource is still available today.

For daily content updates, save the completed Markdown report in the parent
workspace as `科研晨报-YYYY-MM-DD.md` and update the parent's
`研究地图-持续更新.md`. Every daily run must also generate and save both
`空间智能与通用AI科研晨报-YYYY-MM-DD.docx` and
`空间智能与通用AI科研晨报-YYYY-MM-DD.pdf` in the parent workspace. Word,
PDF and the website are all required deliverables. Use the same completed
Markdown source for all formats, retain historical files, and render-check
both exports with the documents/PDF skills. Verify that both files exist and
are readable; include their local download links in the final report alongside
the daily webpage link. Keep these local documents and their QA files out of
the website repository. If one delivery fails, preserve the others, retry and
report the incomplete part explicitly.
Then run `.venv/bin/python scripts/publish.py --source ..` from this checkout.
It fast-forwards, imports completed reports, builds and checks the website,
commits only content changes to `main`, and pushes verified static output to
`gh-pages` for GitHub Pages branch publishing. If `.venv` is absent, create it with
Python 3 and install `requirements.txt`. Never force-push, stash another
person's edits, or publish a partial draft as a completed report.

After pushing, inspect the built-in Pages build/deployment for the returned
`gh-pages` output commit. Wait for the deployment to succeed and read the live
report URL. Verify `deployment.json` if a source-commit receipt is needed. A push alone
does not establish that the site updated. If publication fails, preserve the
local report, fix routine build errors and retry; clearly report any remaining
failure instead of claiming success.

The site reads Markdown from `content/reports/` and the retained legacy
`YYYY-MM-DD-ai-daily.md` files in the repository root. `content/research-map.md`
is the public map. All HTML, archive metadata, full-text search, feeds and
legacy redirects are generated by `scripts/build.py` into ignored `public/`.
`assets/` contains the design and local KaTeX runtime. The publisher builds and
validates locally; GitHub Pages serves the root of `gh-pages` automatically.
Use this branch publishing route so routine updates are built and validated
locally and use the verified built-in Pages deployment. No browser CDN is required.

Use `python scripts/build.py` and `python scripts/check.py` for site changes.
Check the reading layout in a browser for changes affecting appearance.
Do not upload credentials, local evidence downloads, experiment data, private
server details, generated Word/PDF QA directories, or the virtual environment.
Local attachment links are removed by the importer; original workspace files
remain untouched. Preserve existing legacy report URLs.
