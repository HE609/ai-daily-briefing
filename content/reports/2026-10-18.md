## 今日精读顺序

今天我建议的精读顺序是：

**A → GeoState**：先看“状态是什么”的问题。它把几何世界模型从视角相关特征推进到可跨相机查询的场景状态，是 Spatial Intelligence 主线最直接的新增。

**B → Spark-0**：再看“数据如何让接触变得可学习”。HumanTouch 与 SparkArena 同时覆盖数据、模型、评测和真实机器人，能检验跨本体对齐是否真的成立。

**C → Value as Memory（VaM）**：然后看“策略如何记住进度并在部署中继续学习”。它把价值函数从训练标签变成运行时记忆，并给出在线 RL 的真实闭环证据。

**D → 3DCodeVerse**：接着看可编辑、可执行、可验证的 3D 世界代码化，理解空间智能与 agent harness 的结合点。

**E → MLExpert / MPT**：最后看两种自进化路径：一个优化长程实验，一个学习多智能体何时参与；它们适合对照未来的 robot self-improvement 设计。

## 重点论文 / 模型 / 项目

## 1. GeoState: Learning View-Decoupled Geometry States for 3D World Modeling｜P0

**作者与机构**：Hongchang Liu、Jian Liu、Yujuan Ding、Liang Peng、Xun Jiang、Fei Ma、Xing Xu、Yi Bin；同济大学、香港理工大学、腾讯、广东省人工智能与数字经济实验室。**发布时间与性质**：arXiv cs.CV/AI/ML/RO 预印本，2026-10-15 提交；非同行评审。论文：[arXiv](https://arxiv.org/abs/2610.22343)，项目页：[GeoState](https://hongchang-liu.github.io/GeoState-project-page/)。

它解决的是 3D 世界模型的状态污染问题：几何基础模型（GFM）的特征同时携带场景变化与相机变化，导致预测器把“镜头换了”误当成“世界变了”。GeoState 用 scene tokenizer 将多视角 GFM 特征聚合为与视角解耦的场景状态，用 geometry decoder 通过 camera ray 查询所需观测，再由自回归世界模型预测未来状态，并单独建模相机运动。这样同一个上下文尺度可以在整个 rollout 中保持一致，也能在预测相机或外部指定相机下重新解码。

作者报告称，GeoState 在 Waymo 上超过已有 3D world model，支持几何一致的跨视角查询，并零样本泛化到 KITTI 与 nuScenes；这些是论文内部实验，尚无第三方复现。创新点不在更大的视频生成器，而在把“可预测的世界状态”和“观察视角”拆成两个接口，直接对应自动驾驶、机器人观察规划和 real-to-sim 的几何一致性需求。它与 VGGT-World 等“直接在 GFM 特征上预测未来”的工作关系最紧密，改进的是状态定义而非单纯的 backbone。

局限是：论文仍以被动驾驶数据为主，没有证明在动作干预、遮挡恢复或真实机器人闭环中保持状态一致；Waymo/KITTI/nuScenes 的跨数据集迁移也不能等同于跨本体迁移。值得深入阅读，尤其应看 scale consistency、camera-motion branch 和 cross-view query 的消融。代码、权重和数据：目前已确认项目页与论文，未确认公开训练代码或 checkpoint；因此可复现性为“论文级、部分可复现”。轻量验证可以取 20 段 Waymo/KITTI/nuScenes 片段，随机扰动相机轨迹，比较 GeoState 与 VGGT-World 风格 baseline 的跨视角深度、3D 点跟踪和尺度漂移；先不训练大模型，只冻结现成 GFM，验证解耦是否真的减少 camera-induced error。

## 2. Spark-0: Scaling Spatially Aligned Tactile Pretraining for Robot Dexterous Manipulation｜P0

**作者与机构**：Tianxing Chen、Wenwei Lin、Chuqiao Lyu 等；XSpark AI、清华大学、港大 MMLab、香港科技大学（广州）、北京大学。**发布时间与性质**：arXiv cs.RO 预印本，2026-10-15 提交；非同行评审。论文：[arXiv](https://arxiv.org/abs/2610.22342)，项目页：[Spark-0](https://xsparkai.com/Spark-0/)，代码：[XsparkAI/Spark-0](https://github.com/XsparkAI/Spark-0)。

Spark-0 解决接触丰富的灵巧操作中“视觉看不到力、顺应性和初始滑移”的问题。模型是空间对齐的 VTLA：训练时用触觉手套生成 image-space contact map，并用冻结的 3D 几何教师监督视觉 token；另一路编码区域力历史和 3D taxel 状态，条件化 action expert。推理时可以完全去掉触觉输入，也可以在真实机器人上保留触觉，因此同一 checkpoint 覆盖 vision-only 与 tactile-conditioned 部署。

核心数据是 1,000 小时 HumanTouch：32 名操作员、100 多类任务、双手全掌触觉手套、25 个手指关节与 6-DoF 腕部追踪、60 Hz 同步 RGB/姿态/触觉；评测是同一具身上的 SparkArena，分为 7 个 vision-only 仿真任务和 5 个触觉真实机器人任务。作者报告称，Spark-0 在 SparkArena 两条赛道均取得最高平均成功率，并在 Ego Humanoid Manipulation Benchmark 的 8 个聚合指标上排名第一；在相同视觉数据和算力下，保留 1,000 小时触觉监督把 Ego Humanoid vision-only success 从 52.5% 提到 71.7%，SparkArena-Real 从 44.0% 提到 52.0%。这些是作者报告，尚无独立复现。

真正的创新是把触觉当作“教视觉去哪里看”的可规模化监督，而不是只当在线传感器；是否值得深入阅读：是，优先看 contact-map 与 tactile pathway 的匹配消融。与 STAR 等视觉-触觉预训练相比，Spark-0 的 HumanTouch 规模更大、训练与部署路径更清晰。主要局限是数据与机器人手的触觉布局高度绑定，跨手型、跨传感器和跨材质的泛化未充分证明；论文的触觉收益同时包含 contact-map supervision 与 tactile pathway，仍需更细的因果拆分。项目页明确展示代码入口，SparkArena-Sim 代码标为 coming soon；未确认 HumanTouch 原始数据与完整模型权重公开，因此复现状态为“代码部分公开，数据/权重不完整”。轻量验证可做 100 小时/1,000 小时两档小规模预训练，保持 RGB、模型和算力完全相同，仅改变触觉监督；再在未见过的手型或传感器布局上做 zero-shot，区分“触觉帮助学习”与“触觉布局记忆”。

## 3. Value as Memory: Online Value-Guided Post-training for General Robot Policies（VaM）｜P0

**作者与机构**：Wenye Yu、Yijin Chen、Kaiyi Xiong、Wenbo Han、Wendi Chen、Yang Jin、Han Xue、Jun Lv、Cewu Lu、Chuan Wen；上海交通大学、上海人工智能实验室、Noematrix。**发布时间与性质**：arXiv cs.RO 预印本，2026-10-15 提交；非同行评审。论文：[arXiv](https://arxiv.org/abs/2610.22368)，项目页：[VaM](https://virlus.github.io/vam/)，官方实现：[Virlus/VaM](https://github.com/Virlus/vam)。

VaM 针对两个部署痛点：部分可观测让相似画面对应不同动作，离线 post-training 又把失败反馈延迟到下一轮。它让 distributional value expert 的最近几次预测进入 action expert，成为“任务进度记忆”，帮助策略判断进度上升、停滞还是下降；训练流程依次经过行为克隆与进度初始化、TD value learning + advantage-conditioned policy、在线 DAgger，再到稀疏终止奖励下的 autonomous learning。数据采集和值/策略更新并行执行。

作者在 box assembly、laundry folding、magnetic bus assembly 三个真实长程任务上报告：加入 value cache 后平均最终三 checkpoint success 提升 29.4 个百分点；与匹配梯度步预算的离线 RL 相比，在线 autonomous learning 再提升 32.8 个百分点；同预算下在线 schedule 完成约 8 倍 policy iterations，异步采集与训练让每个 gradient step 的记录时间降低约 57.8%。项目页与 GitHub 还给出 I2RT 双臂设置、三相机、LeRobot v2.1 成对 action/value 数据格式和训练脚本。这些数字仍是作者报告，尚无第三方硬件复现。

它与 Physical Intelligence 的 RECAP/π*0.6 体系关系密切，但关键变化是把 value 从“只用于标注或 advantage”推进到运行时输入。是否值得深入阅读：是，重点看 value source matters 与在线/离线预算匹配。局限包括：value cache 可能把错误进度估计固化到动作决策；真实任务数量少，在线 RL 成本和安全约束仍高；GitHub 的环境要求 Ubuntu 24.04、CUDA 12.6、双臂硬件，复现门槛明显。代码已公开，论文训练数据和完整 checkpoint 未全部确认，复现状态为“代码与数据格式公开，硬件与权重不完整”。轻量验证可在 LIBERO 或自建两阶段任务中构造“画面相同、阶段不同”的状态，比较无 cache、随机 cache、真实 value cache 三种策略的 nearby-action、恢复率和错误进度敏感性；若没有真实机器人，可先用离线轨迹和稀疏 reward 模拟 online/offline update schedule。

## 4. Mem4Act: Learning Effective Latent Memory for Long-Horizon Robotic Manipulation｜P1

**作者与机构**：Yun Zhang、Zhiyu Huang、Tianhui Cai、Chen Tang、Wei Wang、Jiaqi Ma；加州大学洛杉矶分校、北卡罗来纳州立大学。**发布时间与性质**：arXiv cs.RO 预印本，2026-10-15 提交；非同行评审。论文：[arXiv](https://arxiv.org/abs/2610.22323)，项目页：[Mem4Act](https://handsomeyun.github.io/Mem4Act/)。

Mem4Act 不把长历史直接塞给策略，而是学习一个固定容量、持续更新的 latent memory。方法包含多粒度时间聚合、QA supervision 保留语义信息、关键帧 DINO feature reconstruction 保留细粒度视觉证据，以及 memory-first 两阶段训练，刻意让 action policy 真正依赖 memory。目标是同时保留“任务状态”和“稍后仍有用的视觉细节”，避免 raw history 的 token/注意力爆炸，也避免语言摘要丢掉接触与外观线索。

作者在 RoboMME、RMBench 和四个真实操作任务上报告 success 49.88%、61.0% 和 81.5%，并通过消融指出 temporal aggregation、互补 memory supervision 和 memory-first training 都有贡献。与 key-frame selection、语言 summary、压缩视觉 token 的工作相比，它的区别是把 memory 训练成可被策略使用的状态接口，而不是单纯的历史压缩器。值得读，但需把“记忆有效”与“额外 QA/关键帧监督有效”分开。

是否值得深入阅读：有条件，适合研究长程 memory interface，但需要把监督收益和记忆收益拆开。局限是 benchmark 仍以短到中程操作为主，未证明 memory 对物理动力学或跨任务迁移的因果记忆；QA 监督和 DINO 重建可能带来额外标注/教师偏差；论文未确认代码、权重或数据公开，复现状态为“论文级”。轻量验证可在 3 个带隐藏信息的长程任务上做四路对照：全帧历史、关键帧、语言摘要、固定 latent memory；分别测 token budget、遮挡后恢复、阶段识别和 action shuffle，避免只报告最终成功率。

## 5. Gen4P: Video Generators are 4D Perceivers｜P1

**作者与机构**：Yitong Xia、Zeren Jiang、Chuanxia Zheng；南洋理工大学 Physical Vision Group、牛津大学 Visual Geometry Group。**发布时间与性质**：arXiv cs.CV 预印本，2026-10-15 提交；非同行评审。论文：[arXiv](https://arxiv.org/abs/2610.22371)，项目页：[gen4p.github.io](https://gen4p.github.io/)，代码仓库：[yitongx/Gen4P](https://github.com/yitongx/Gen4P)。

Gen4P 的问题是：视频生成器已经学到大量时空结构，但通常要多步去噪，不能直接当 4D 感知器。它把预训练视频生成器的 clean video latent 做一次 encoder pass，再用轻量 cross-attention decoder 按需查询 3D 点轨迹、视频深度、相机姿态等属性；continuous-time query 提供时间灵活性，并把一个冻结的 video-depth LoRA 作为几何先验插入，不增加可训练参数。

作者报告称，Gen4P 在 3D point tracking、video depth 和 camera pose estimation 上达到 SOTA 或有竞争力，并在野外视频中保持复杂运动和细结构。它和 4D-RGPT、L4P 等统一 4D 感知工作互补：Gen4P 的重点是“复用视频生成预训练并通过 query 解码”，而不是新建多任务 backbone。它对 Spatial Intelligence 的意义是把“生成式世界先验”转成可查询的几何与运动状态。

是否值得深入阅读：是，适合视频表征与 4D 状态接口方向；复现前先确认权重和运行脚本。代码仓库已经公开，但 README 的 Installation/Usage 仍是 WIP，未见公开权重或一键 demo；因此复现状态为“代码骨架公开，权重与运行脚本未就绪”。局限包括单目尺度歧义、对视频生成器的具体版权/权重依赖，以及尚未证明动作条件或真实机器人闭环。轻量验证可冻结任意公开视频生成器/视频 MAE，先只训练 query decoder，在 TAP-Vid、Depth、Pose 三个小子集上比较单次 encoder 与多步去噪的质量/延迟；再做 camera trajectory perturbation，检查 4D 一致性是否真的来自生成式预训练。

## 6. 3DCodeVerse: Exploring 3D Worlds as Code｜P1

**作者与机构**：Yipeng Gao、Ziyao Zeng、Jinfa Huang、Yijiang Li 等；南加州大学、耶鲁大学、罗切斯特大学、加州大学圣迭戈分校、哥伦比亚大学、南洋理工大学、Google DeepMind、Philo Labs 等。**发布时间与性质**：arXiv cs.CV/AI 预印本，2026-10-15 提交；非同行评审。论文：[arXiv](https://arxiv.org/abs/2610.22341)，项目页：[3DCodeVerse](https://3dcodeverse.com/)，官方代码：[gaoypeng/3dcodeverse](https://github.com/gaoypeng/3dcodeverse)，数据集：[Hugging Face 3DCodeVerse](https://huggingface.co/datasets/ilabai/3dcodeverse)。

它把“生成 3D 世界”改写成“生成可执行、可编辑、可验证的 3D 程序”。3DCodeVerse-2M 收集约 200 万份独立 3D executable programs，保留源文件、资产、描述和验证记录；Harness 是多智能体 DAG，负责规划、写代码、执行、测量、渲染、视觉判断和自动修订，无需人在生成循环中逐个修改。训练与评估同时覆盖 Blender Python、Three.js、OpenGL、URDF 等代码形式。

论文报告在 100 个 text-to-3D object prompts 上，Harness 相比原生 coding harness 明显提升人类偏好和 judge score；摘要给出相对 Claude Design（3D Object）的 90% pairwise human-eval 胜率，但这是作者报告，需注意比较基座与提示词条件。它与传统 text-to-3D mesh/NeRF/3DGS 的关系是把对象、场景、图形和可动资产统一到“程序 + 运行时验证”接口，直接连接 spatial reasoning、agent self-correction 和可编辑世界生成。

是否值得深入阅读：是，优先级仅次于 GeoState/Spark-0，因其代码、数据和验证闭环都已公开。这是本期可复现性最好的条目之一：Apache-2.0 代码、数据页、Harness、LoRA/DPO recipe 和评估脚本均可见；大规模数据的下载和执行成本仍需核对，模型权重不是论文的主要发布物。局限是执行正确不等于物理正确，90% 胜率只覆盖 100 个对象提示，尚未证明跨引擎、跨仿真器或真实机器人可用。轻量验证可从 50 个场景提示开始，比较原生 code agent、单次执行检查、完整 Harness 三种设置，分别统计可运行率、几何约束满足率、编辑后保持率和跨 Blender/MuJoCo 的资产可迁移性。

## 7. MLExpert: Towards a Generalist Agentic Model for Autonomous Machine Learning Engineering｜P1

**作者与机构**：Shangheng Du、Jinxin Shi、Shuaiyu Zhang 等；华东师范大学、上海人工智能实验室。**发布时间与性质**：arXiv cs.AI/CL/ML 预印本，2026-10-15 提交；非同行评审。论文：[arXiv](https://arxiv.org/abs/2610.22344)，代码：[InternScience/MLExpert](https://github.com/InternScience/MLExpert)，权重：[Hugging Face](https://huggingface.co/InternScience/MLExpert)。

MLExpert 研究的是 AI4AI/递归自改进的可执行版本：模型需要在持续实验中选下一步、读结果、修改代码、保留候选解，而不是一次输出脚本。作者构建 Kaggle-MLE Factory 生成可执行任务和交互 harness，用 hierarchical agentic SFT 把通用工具能力迁到 MLE，再用 Windowed Interaction RL（WIRL）把两次实验结果之间的多轮决策视为一个共享 outcome reward 的 execution window，并在轨迹结束前做异步策略修正。

作者报告的 35B MoE MLExpert 在 MLE-Bench Lite 上把 base model 的 any-medal rate 从 37.9% 提到 72.7%，在通用 Claude Code harness 上从 42.4% 提到 69.7%；在 NatureBench Lite 的十个科学任务上，Surpass-SOTA 从 0 提到 50%。这些结果依赖作者的任务工厂、评测脚手架和模型服务配置，暂无独立复现。它与 Agentic-TTT、AdaRSI、CoWorld Reasoner 的关系是把“自我改进”落到可执行实验反馈与中间 credit assignment，适合当作 robot self-improvement 的非物理对照。

是否值得深入阅读：是，适合把 AI4AI 的 credit assignment 迁移到 robot self-improvement；先做小模型替代实验。代码、35B BF16 权重和 Apache-2.0 model card 已公开，但双 GPU 推理、长上下文和 Kaggle/科学任务环境仍有较高算力与数据要求；Kaggle 生成的 split/scoring code 需要人工检查。局限是任务仍主要是软件/数据科学，不能直接证明物理世界中的安全自进化，也可能把 harness 优化误认为模型能力。轻量验证可用 7B/14B 开源模型与 3 个本地可复现实验（超参搜索、数据清洗、小型分类器）复刻 WIRL：比较只看最终 reward、每阶段 reward、异步中途更新三种 credit assignment，并记录失败修复是否可迁移到新任务。

## 8. Learning Self-Orchestration in Decentralized Agent Swarms｜P1

**作者与机构**：Guowei Xu、Zhenting Qi、Amani Kiruga、Himabindu Lakkaraju、Yilun Du；哈佛大学。**发布时间与性质**：arXiv cs.MA/AI/CL 预印本，2026-10-15 提交；非同行评审。论文：[arXiv](https://arxiv.org/abs/2610.22322)，代码与模型：[Embodied-Minds-Lab/MPT](https://github.com/Embodied-Minds-Lab/MPT)。

Market-based post-training（MPT）不预先固定谁负责什么，而让每个 agent 对当前行动“出价”，最高出价者参与执行，并从集体结果获得局部训练信用。它联合学习 action policy 与 bidding policy，在没有中心协调器的情况下让参与模式随能力变化。实验覆盖 embodied crafting、robot navigation 和 deep research；仓库明确提供三 agent society、单 agent baseline、训练/评估脚本、Minecraft 与导航数据，以及 Hugging Face checkpoint。

论文报告 MPT 相对 monolithic post-training 和其他 coordination strategy 有收益，较大 population 在 agent dropout 下损失更小，且在相关任务上适应更快。仓库把三个 agent 分成 Logger/Miner/Smith、Turner/Mover/Stopper、Searcher/Opener/Finder，并提供 `Xkev/*_society` 权重，这使它比只给概念的 swarm paper 更接近可复现实验。尚无第三方验证，且论文未在摘要中给出跨任务统一数值，因此应把结论理解为机制性证据。

是否值得深入阅读：是，尤其适合做多智能体掉线、角色变化和 reward attribution 的对照。创新点是把“何时参与”作为可学习的行动空间；局限是每个 agent 只能发出自己的 action slice，环境已预设角色和可分解性，不能直接代表开放世界机器人群体。代码是 Apache-2.0，模型、训练数据和评估脚本均可见，但依赖多 GPU、Minecraft/Habitat/搜索服务。轻量验证可先用三个小型可分解任务，做 fixed-role、random-bid、learned-bid 三组，测 task success、credit variance、agent dropout 和新 population size；再把“出价”替换成 uncertainty/value signal，观察它是否与 VaM 的进度记忆互补。

## Spatial Intelligence / Frontier 扫描

本轮已扫描 World Labs、Generalist AI、Physical Intelligence、Google DeepMind/Robotics、NVIDIA Robotics/Cosmos/GR00T、Figure、Skild AI、Field AI、1X、Meta FAIR、Anthropic、Toyota Research Institute，以及 Stanford、Berkeley、MIT、CMU、Princeton 和主要中国团队的公开 research/news/project/GitHub/Hugging Face 入口。

窗口内唯一新增且值得单列的是 Google Research 的 **VERID**：官方文章发表于 2026-10-16，配套技术报告《Semantic Representation for Agentic Self-Play in Automated Laboratories》由 Google Research、Google Cloud、Google DeepMind 作者署名。官方链接：[Google Research 文章](https://research.google/blog/grounding-ai-agents-in-biological-reality-building-blocks-for-autonomous-wet-labs/)，[VERID 技术报告](https://www.gstatic.com/science-ai/verid_semantic_lab.pdf)。

是否值得深入阅读：是，作为 physical state grounding 与可审计 agent infrastructure 的官方参照。VERID 把液体处理工作台表示为持续存在的 3D volumetric entity tree，跟踪机械臂几何、容器、well volume、试剂和 pipette tip；四个核心服务是 queryable introspection、time-compressed simulation、multimodal trace persistence 和 safe execution。官方案例包括仿真门控拦截不可能的 8-channel aspiration、plate-reader 故障后的中途恢复，以及通过同步视频/执行轨迹定位液体混合偏差；文章还报告在三轮 aptamer 设计-实验-分析循环中，myoglobin 与 α-thrombin 的 on-target hit rate 上升。证据性质是官方文章 + 官方技术报告，尚无同行评审、公开模型权重或独立第三方复现；VERID 本身没有完整开源仓库，依托开源 PyLabRobot。它不是通用 robot foundation model，却是 Spatial Intelligence、physical state grounding、agent self-evolution 和实验可审计性的强交叉信号。

主要官方入口没有窗口内足以进入 Top Papers 的新 World Model/VLA 重大发布：World Labs 最新可见重点仍是 Atlas 与 real-to-sim-to-real，Generalist 仍是 GEN-1.5，Physical Intelligence 的 Pi API beta 是 10 月 13 日的上一窗口条目，NVIDIA 的 GR00T/Cosmos 最新公开版本也早于本窗口，Meta/Anthropic/TRI 入口未见新的同量级模型或权重。Google DeepMind 另有一篇 arXiv 预印本 **A team of Gemini 4 Argon agents beats Minecraft**（[arXiv 2610.22319](https://arxiv.org/abs/2610.22319)），报告四个 Gemini 4 Argon agent 通过 Mineflayer、共享记忆和聊天，在随机 Easy 世界中 27 小时 14 分钟击败 Ender Dragon，写了 2,783 个程序并死亡 605 次；这是单次 author-reported demonstration，不是成功率、像素级感知或第三方复现，应作为 agent long-horizon watch item，而不是机器人能力证据。

## 今日研究地图

| 问题分类 | 今日映射 | 近期趋势 | 尚未解决的 gap | 可形成论文的机会 |
|---|---|---|---|---|
| 几何状态与 4D 感知 | GeoState、Gen4P | 从像素/视角特征转向可查询、可跨相机的状态 | 动作干预下的因果几何、尺度与长期漂移 | 用相机扰动、动作反事实和跨数据集重访构造“state validity”评测 |
| 触觉与跨本体对齐 | Spark-0、HumanTouch、SparkArena | 触觉从部署输入变为大规模视觉监督 | 触觉布局、手型、材质和频率变化的迁移 | 统一 contact-map、taxel、力历史的跨传感器适配器与因果消融 |
| 长程记忆与在线适应 | VaM、Mem4Act | value history 与 latent memory 进入策略接口 | 错误记忆、阶段泄漏、在线 RL 安全和成本 | “进度记忆 vs 视觉记忆”统一基准，单独测恢复而非只测终局 success |
| 可验证世界生成 | 3DCodeVerse、VERID | 生成结果带执行、几何、状态和 provenance 检查 | 可执行不等于物理正确，验证器自身可能偏置 | 让 3D code harness 与 MuJoCo/Isaac/真实机器人共享同一 provenance schema |
| Agent 自进化与群体协作 | MLExpert、MPT、Gemini Argon | 从单步 tool use 转向长程实验、出价、共享记忆 | credit assignment、任务外泛化、掉线恢复和安全边界 | 将 uncertainty/value cache 接入 learned bidding，做可审计的 self-improving swarm |

今天最明显的趋势是三个接口正在合流：**空间状态接口**（GeoState/Gen4P）、**进度与历史接口**（VaM/Mem4Act）以及**验证与执行接口**（3DCodeVerse/VERID）。它们共同指向一个比“视频预测”更严格的研究问题：模型是否能在行动后维护可查询、可校验、能指导下一步的世界状态。

## 今日研究机会与轻量验证

1. **几何状态因果审计**：冻结一个公开 GFM，在 20 段视频上分别扰动相机、物体动作和时间采样，比较 view-consistency、scale drift、point tracking 和 action-conditioned error。若 GeoState 的优势只在相机扰动下出现，而在动作干预下消失，说明它更像几何表示改进而非 world model。

2. **触觉监督的最小可行复现**：取 100 小时和 1,000 小时 HumanTouch 子集，保持 RGB、模型大小与训练步数一致；做 vision-only、contact-map-only、tactile-pathway-only、两者联合四组。先在 SparkArena-Sim 风格的视觉任务上验证触觉是否真的改善无触觉部署，再做未见手型的小规模真实测试。

3. **进度记忆对比**：在 LIBERO 或自建长程任务中构造“同画面不同阶段”的 pair，比较无记忆、VaM value cache、Mem4Act latent、语言摘要。除终局成功外，加入 recovery rate、nearby-action sensitivity、阶段分类和 value shuffle，直接测记忆是否携带因果进度。

4. **可验证 3D 世界闭环**：用 50 个场景提示比较原生 code agent、单执行检查、3DCodeVerse Harness；再把生成资产导入 MuJoCo/Isaac，测碰撞、可编辑性、关节限制和跨引擎一致性。把每次生成的代码、渲染、测量和修订记录成 provenance，验证“可审计”能否预测真实可用性。

5. **自进化 agent 的低算力替代**：用 7B/14B 模型复刻 MLExpert 的 WIRL 或 MPT 的 bidding，只保留 3 个本地任务和 3 个 agent。比较最终 reward、每阶段 reward、异步更新和 dropout；若 learned bid 只在固定角色任务有效，应把结论限制在 orchestration scaffold，而不要外推为通用群体智能。

## 证据状态与可复现性

- **GeoState**：arXiv 预印本 + 项目页；作者实验报告 Waymo/KITTI/nuScenes；未确认公开代码、权重或数据；无第三方验证。
- **Spark-0**：arXiv 预印本 + 官方项目页 + GitHub 入口；HumanTouch 1,000 小时与 SparkArena 已定义，部分代码标为 coming soon；完整数据/权重未确认；无第三方验证。
- **VaM**：arXiv 预印本 + 项目页 + Apache-2.0 官方实现；训练/部署脚本和 LeRobot 数据格式公开，真实硬件与完整 checkpoint 不完整；无第三方验证。
- **Mem4Act**：arXiv 预印本 + 项目页；作者报告 RoboMME、RMBench 和真实任务结果；未确认代码、权重、数据；无第三方验证。
- **Gen4P**：arXiv 预印本 + GitHub/项目页；代码仓库公开但安装与用法仍 WIP，未确认权重；无第三方验证。
- **3DCodeVerse**：arXiv 预印本 + Apache-2.0 GitHub + 3DCodeVerse-2M 数据集页 + Harness/recipe；代码与数据入口最完整，但大规模运行成本和模型权重需单独核验；无第三方方法复现。
- **MLExpert**：arXiv 预印本 + GitHub + 35B BF16 Hugging Face 权重，Apache-2.0；任务工厂与评估脚手架公开，需双 GPU/长上下文；无第三方复现。
- **MPT**：arXiv 预印本 + Apache-2.0 GitHub + Hugging Face society/single checkpoints + 训练数据；复现路径最清楚但依赖 Minecraft/Habitat/搜索服务与多 GPU；无第三方复现。
- **VERID**：Google Research 官方文章 + 16 页技术报告，官方/技术报告证据；依托 PyLabRobot，未发现 VERID 完整代码、权重或独立 benchmark；无同行评审和第三方验证。
- **Gemini 4 Argon Minecraft**：arXiv 预印本与作者运行记录；单次 27 小时演示，Mineflayer 提供结构化状态，模型无公开权重；不能当作机器人闭环或泛化率证据。
